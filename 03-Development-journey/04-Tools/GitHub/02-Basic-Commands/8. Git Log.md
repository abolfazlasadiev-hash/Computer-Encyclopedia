## 1. Overview

The `git log` command displays the commit history of a Git repository. It allows you to inspect previous commits, understand how a project has evolved, identify who made changes, and find specific points in the repository's history.

Every time you create a commit with `git commit`, Git records information about that commit, including:

- A unique commit hash.
    
- The author of the commit.
    
- The date of the commit.
    
- The commit message.
    
- A reference to its parent commit or commits.
    
- A snapshot representing the repository's tracked content.
    

The `git log` command reads this information and presents it in chronological order, starting with the most recent commit by default.

### Why Is `git log` Important?

You can use `git log` to:

- Review the history of a project.
    
- Find a specific commit.
    
- Identify who made a change.
    
- Read previous commit messages.
    
- Compare different points in history.
    
- Investigate bugs and unexpected changes.
    
- Understand how branches have developed.
    
- Find commit hashes for other Git commands.
    

**Important:** `git log` only displays repository history. It does not modify files, create commits, or change branches.

## 2. Key Concepts

Before using `git log`, it is useful to understand several concepts related to Git history.

### 2.1 Commit

A commit is a recorded snapshot of the repository at a particular point in time.

Each commit contains metadata and references to the content it records.

Example:

```
commit a1b2c3d4e5f6...
Author: John Smith <john@example.com>
Date:   Mon Nov 2 10:30:00 2026 +0100

    Add user authentication
```

### 2.2 Commit Hash

Every Git commit has a unique identifier called a commit hash.

Git normally uses SHA-1 commit identifiers, which are 40 hexadecimal characters long. Repositories can also use SHA-256 object formats.

Example:

```
a1b2c3d4e5f6789012345678901234567890abcd
```

You can use a commit hash to reference a specific commit.

Git also accepts an abbreviated hash when it uniquely identifies a commit in the repository.

Example:

```
git show a1b2c3d
```

### 2.3 Author and Committer

Git stores two different identities for a commit:

- **Author:** The person who originally wrote the changes.
    
- **Committer:** The person who created the commit object.
    

These identities are often the same, but they can differ when commits are applied, rebased, or otherwise recreated.

### 2.4 HEAD

`HEAD` is a reference to the current position in the repository's history.

In a typical repository, `HEAD` points to the latest commit on the currently checked-out branch.

Example:

```
git log HEAD
```

### 2.5 Parent Commit

A commit usually references one parent commit.

The first commit in a repository has no parent. A merge commit can have multiple parents.

Git uses these relationships to build the repository's commit history.

### 2.6 Commit History

The commit history is the sequence or graph of commits in a repository.

A simple history might look like this:

```
A --- B --- C --- D
```

Here, each letter represents a commit, and each commit is connected to its parent.

Branches and merges can create more complex histories.

### 2.7 References and Revisions

Git provides several ways to identify commits:

|Reference|Meaning|
|---|---|
|`HEAD`|Current commit|
|`HEAD~1`|First parent of HEAD|
|`HEAD~2`|Two generations back along the first-parent chain|
|`HEAD^`|First parent of HEAD|
|`HEAD^2`|Second parent of a merge commit|
|`main`|Commit currently referenced by the `main` branch|
|`a1b2c3d`|A commit identified by its abbreviated hash|

These references are useful when filtering or inspecting history.

## 3. Syntax

The general syntax of `git log` is:

```
git log [options] [revision-range] [[--] path...]
```

### Parameters

|Parameter|Description|
|---|---|
|`options`|Controls the output format and filtering behavior|
|`revision-range`|Specifies which commits should be displayed|
|`--`|Separates revision arguments from file paths|
|`path`|Limits the history to changes affecting specified paths|

You can run `git log` without additional arguments to display the current branch's reachable commit history.

## 4. Git Log Commands

### 4.1 Display the Commit History

```
git log
```

Displays the commit history reachable from the current `HEAD`.

The default output includes:

- Commit hash.
    
- Author.
    
- Date.
    
- Commit message.
    

Example:

```
commit a1b2c3d4e5f6789012345678901234567890abcd
Author: John Smith <john@example.com>
Date:   Mon Nov 2 10:30:00 2026 +0100

    Add user authentication

commit b2c3d4e5f6789012345678901234567890abcde1
Author: Sarah Johnson <sarah@example.com>
Date:   Sun Nov 1 15:20:00 2026 +0100

    Update project documentation
```

The newest commit appears first.

### 4.2 Display a Compact History

```
git log --oneline
```

Displays each commit on a single line.

Example:

```
a1b2c3d Add user authentication
b2c3d4e Update project documentation
c3d4e5f Fix login validation
d4e5f6a Initial project setup
```

This format is useful when you want to scan many commits quickly.

### 4.3 Display a Graph of the Commit History

```
git log --graph
```

Displays an ASCII graph representing the commit structure.

Combine it with `--oneline` and `--all`:

```
git log --oneline --graph --all
```

Example:

```
* a1b2c3d (HEAD -> main) Add authentication
| * b2c3d4e (feature/profile) Add profile page
|/
* c3d4e5f Update homepage
* d4e5f6a Initial commit
```

This makes it easier to understand branches and merges.

### 4.4 Display All Branch Histories

```
git log --all
```

Displays commits reachable from all references included in the repository.

For a more readable graph:

```
git log --oneline --graph --all
```

This is especially useful when investigating commits on other local or remote-tracking branches.

**Note:** `--all` does not automatically download new remote history. Run `git fetch` first if you need the latest remote-tracking information.

### 4.5 Limit the Number of Commits

```
git log -n 5
```

Displays the five most recent commits.

You can also use:

```
git log -5
```

Both forms limit the number of commits displayed.

### 4.6 Display Full Commit Information

```
git log --format=full
```

Displays more detailed commit information, including author and committer details.

Another option is:

```
git log --format=fuller
```

This includes additional date information for both the author and committer.

### 4.7 Display a Custom Commit Format

```
git log --pretty=format:"%h - %an, %ar : %s"
```

Displays commit information using a custom format.

Example:

```
a1b2c3d - John Smith, 2 hours ago : Add authentication
b2c3d4e - Sarah Johnson, 1 day ago : Update documentation
```

Useful format placeholders:

|Placeholder|Description|
|---|---|
|`%H`|Full commit hash|
|`%h`|Abbreviated commit hash|
|`%an`|Author name|
|`%ae`|Author email|
|`%cn`|Committer name|
|`%ce`|Committer email|
|`%ad`|Author date|
|`%cd`|Committer date|
|`%ar`|Author date, relative format|
|`%cr`|Committer date, relative format|
|`%s`|Commit subject|
|`%b`|Commit message body|
|`%d`|Ref names, such as branches and tags|

You can also use:

```
git log --pretty=short
```

or:

```
git log --pretty=medium
```

Git provides several built-in output formats.

### 4.8 Display Changes Introduced by Each Commit

```
git log -p
```

Displays commit history together with the patch introduced by each commit.

This is useful when you want to understand not only which commits were created, but also what changes they introduced.

Limit the output to the latest two commits:

```
git log -p -2
```

### 4.9 Display Commit Statistics

```
git log --stat
```

Displays a summary of the files changed in each commit.

Example:

```
commit a1b2c3d
    Add authentication

 src/auth.js | 25 +++++++++++++++++++++
 src/app.js  |  3 ++-
 2 files changed, 27 insertions(+), 1 deletion(-)
```

This is useful for reviewing the general scope of a commit without displaying the full patch.

### 4.10 Display Only Changed File Names

```
git log --name-only
```

Displays commit information followed by the names of files changed in each commit.

For a shorter output:

```
git log --oneline --name-only
```

### 4.11 Filter Commits by Author

```
git log --author="John Smith"
```

Displays commits whose author information matches the specified pattern.

You can also search by email:

```
git log --author="john@example.com"
```

### 4.12 Filter Commits by Commit Message

```
git log --grep="authentication"
```

Displays commits whose commit messages match the specified pattern.

By default, Git searches using a case-sensitive regular expression.

For a case-insensitive search:

```
git log --grep="authentication" -i
```

### 4.13 Filter Commits by Date

Display commits after a specific date:

```
git log --since="2026-01-01"
```

Display commits before a specific date:

```
git log --until="2026-06-30"
```

Use both options together:

```
git log --since="2026-01-01" --until="2026-06-30"
```

You can also use relative dates:

```
git log --since="2 weeks ago"
```

**Note:** These date filters use commit date information, which normally refers to the author date unless options such as `--author-date-order` affect ordering. Git also provides `--committer-date` when you need to filter by committer date.

### 4.14 Display History for a Specific File

```
git log -- README.md
```

Displays commits that affected `README.md`.

For a more compact output:

```
git log --oneline -- README.md
```

The `--` separator tells Git that the following argument is a path rather than a revision.

### 4.15 Follow a File Across Renames

```
git log --follow -- README.md
```

Attempts to follow the history of a file across renames.

This is particularly useful when a file has been renamed and you want to inspect its earlier history.

**Note:** `--follow` works with a single file path and is based on Git's rename detection.

### 4.16 Display History for a Specific Branch

```
git log main
```

Displays commits reachable from the `main` branch.

You can also inspect another branch:

```
git log feature/login
```

This does not switch branches or modify the working directory.

### 4.17 Compare the History of Two Branches

```
git log main..feature/login
```

Displays commits reachable from `feature/login` that are not reachable from `main`.

To inspect commits reachable from `main` but not from `feature/login`:

```
git log feature/login..main
```

To compare both sides:

```
git log --left-right --oneline main...feature/login
```

This displays commits reachable from either branch but not both.

Example:

```
< a1b2c3d Fix homepage layout
> b2c3d4e Add login page
```

- `<` represents commits unique to the first branch.
    
- `>` represents commits unique to the second branch.
    

### 4.18 Display Commits Between Two Dates

```
git log --since="2026-03-01" --until="2026-03-31"
```

Displays commits whose relevant commit dates fall within the specified range.

You can combine date filtering with other options:

```
git log --oneline --author="John Smith" --since="1 month ago"
```

### 4.19 Display Commits That Changed a Specific String

```
git log -S"function login" -- src/auth.js
```

Searches for commits that changed the number of occurrences of the specified string.

This is called a _pickaxe search_.

Another option is:

```
git log -G"function\s+login" -- src/auth.js
```

`-G` searches for commits whose added or removed lines match a regular expression.

The difference:

- `-S` looks for changes in the number of occurrences of a string.
    
- `-G` looks for added or removed lines matching a regular expression.
    

These options are useful when investigating when a particular piece of code was introduced or changed.

### 4.20 Display a Commit and Its Details

Although `git show` is designed for inspecting individual Git objects, you can use `git log` to identify a commit first:

```
git log --oneline
```

Then inspect a specific commit:

```
git show a1b2c3d
```

This displays the commit metadata and its changes.

## 5. Practical Examples

The following examples demonstrate common workflows using `git log`.

### Example 1: Review the Latest Commits

```
git log --oneline -5
```

Displays the five most recent commits in a compact format.

### Example 2: Understand Branch Structure

```
git log --oneline --graph --all
```

Displays a visual representation of the commit history across local references.

### Example 3: Find Commits Made by a Specific Developer

```
git log --author="John Smith" --oneline
```

Displays commits authored by John Smith.

### Example 4: Find a Commit Related to a Feature

```
git log --grep="login" -i --oneline
```

Searches commit messages for references to login functionality.

### Example 5: Review Changes Made to a File

```
git log -p -- src/auth.js
```

Displays the history and patches for `src/auth.js`.

### Example 6: Find When a File Was Renamed

```
git log --follow --name-status -- README.md
```

Displays the file's history while attempting to follow its renames.

### Example 7: Find Commits Created During the Last Week

```
git log --since="1 week ago" --oneline
```

Displays commits from the last week.

### Example 8: Find Commits Unique to a Feature Branch

```
git log main..feature/login --oneline
```

Displays commits that are reachable from `feature/login` but not from `main`.

### Example 9: Find When a Function Was Introduced or Changed

```
git log -S"function login" --oneline -- src/auth.js
```

Searches for commits that changed the number of occurrences of `function login` in the specified file.

### Example 10: Create a Custom History Report

```
git log --pretty=format:"%h | %an | %ad | %s" --date=short
```

Example output:

```
a1b2c3d | John Smith | 2026-11-02 | Add authentication
b2c3d4e | Sarah Johnson | 2026-11-01 | Update documentation
c3d4e5f | John Smith | 2026-10-30 | Fix validation
```

This format is useful for quickly reviewing commit authors, dates, and messages.

## 6. Common Errors and Troubleshooting

### 6.1 `fatal: not a git repository`

**Cause:**

You are running `git log` outside a Git repository.

**Solution:**

Navigate to the repository directory:

```
cd my-project
```

Then run:

```
git log
```

### 6.2 No Commit History Is Displayed

**Possible cause:**

The repository does not contain any commits yet.

**Solution:**

Check the repository status:

```
git status
```

If no commit exists, create an initial commit:

```
git add .
git commit -m "Initial commit"
```

Then run:

```
git log
```

### 6.3 A Branch Name Is Not Recognized

**Example:**

```
fatal: ambiguous argument 'feature/login': unknown revision or path not in the working tree
```

**Possible causes:**

- The branch does not exist.
    
- The branch name is misspelled.
    
- The remote branch has not been fetched.
    

**Solutions:**

List local branches:

```
git branch
```

List local and remote-tracking branches:

```
git branch -a
```

Update remote-tracking references:

```
git fetch
```

### 6.4 A File's Earlier History Is Missing

**Possible cause:**

The file was renamed or moved.

**Solution:**

Use:

```
git log --follow -- path/to/file
```

Remember that rename detection is heuristic, so Git may not identify every rename in every situation.

### 6.5 The Output Is Too Long

**Cause:**

The repository has many commits, or you are displaying detailed patches.

**Solutions:**

Limit the number of commits:

```
git log -5
```

Use compact output:

```
git log --oneline
```

Display only commit statistics:

```
git log --stat
```

### 6.6 A Commit Message Search Returns No Results

**Possible causes:**

- The search text does not match any commit message.
    
- The search is case-sensitive.
    
- The commit exists in a different branch's history.
    

**Solutions:**

Use case-insensitive search:

```
git log --grep="login" -i
```

Search all references:

```
git log --all --grep="login" --oneline
```

### 6.7 The Latest Remote Commits Are Missing

**Cause:**

Your local repository may not have updated its remote-tracking references.

**Solution:**

Fetch the latest information:

```
git fetch
```

Then inspect the updated history:

```
git log --all --oneline --graph
```

**Important:** `git fetch` updates remote-tracking references but does not automatically merge remote changes into your current branch.

## 7. Best Practices

1. **Use** `**--oneline**` **for quick reviews.**  
    It makes long commit histories easier to scan.
    
2. **Use** `**--graph --all**` **to understand branch relationships.**  
    It helps you visualize merges and parallel development.
    
3. **Write meaningful commit messages.**  
    Clear commit messages make history searches more useful.
    
4. **Use** `**--since**` **and** `**--until**` **to narrow the history.**  
    Date filters help when investigating changes from a specific period.
    
5. **Use** `**--author**` **to identify contributions.**  
    This is useful when reviewing the work of a particular developer.
    
6. **Use** `**--**` **before file paths.**  
    It clearly separates path arguments from revision arguments.
    
7. **Use** `**-p**` **when you need to understand actual code changes.**  
    Commit messages alone may not explain the full implementation.
    
8. **Use** `**--follow**` **when investigating renamed files.**  
    It can help preserve the context of a file's history.
    
9. **Run** `**git fetch**` **before reviewing recent remote history.**  
    This ensures your remote-tracking references are up to date.
    
10. **Avoid relying only on commit messages during investigations.**  
    Combine `git log` with `git show` and `git diff` to understand what actually changed.
    
11. **Use full commit hashes when precision matters.**  
    Abbreviated hashes are convenient, but a full hash uniquely identifies a commit.
    
12. **Remember that** `**git log**` **displays reachable history.**  
    A commit that is not reachable from the selected references may not appear in the output.

## 11. Final Summary

The `git log` command is one of the most important tools for understanding the history of a Git repository.

It allows you to inspect commits, identify authors, search commit messages, review file history, examine code changes, and understand branch relationships.

The most useful commands to remember are:

```
git log
git log --oneline
git log --oneline --graph --all
git log -p
git log --author="Name"
git log --grep="keyword"
git log --since="1 week ago"
git log -- path/to/file
```

**Remember:**

- `git log` displays commit history.
    
- `git show` provides detailed information about a specific commit.
    
- `git diff` compares changes between files, commits, and branches.
    
- `git fetch` updates remote-tracking references before you inspect recent remote history.
    

Understanding `git log` helps you investigate changes, follow project development, and work confidently with Git history.
