# راهنمای جامع نصب برنامه در لینوکس

در لینوکس روش‌های مختلفی برای نصب، به‌روزرسانی، حذف و مدیریت نرم‌افزارها وجود دارد. برخلاف ویندوز که معمولاً از فایل‌های `.exe` و `.msi` استفاده می‌کنیم، در لینوکس می‌توانیم از مخازن رسمی، مدیران بسته، فایل‌های مستقل، ابزارهای خط فرمان، فروشگاه‌های نرم‌افزاری، کانتینرها و حتی کامپایل‌کردن کد منبع استفاده کنیم.

این راهنما ابزارها و روش‌های اصلی و تخصصی نصب نرم‌افزار در لینوکس را به‌صورت ساختارمند، همراه با مثال‌های عملی، معرفی می‌کند.

## ۱. دسته‌بندی کلی روش‌های نصب

۱. مدیران بسته و مخازن رسمی

روش استاندارد و معمولاً پیشنهادی

`APT`، `DNF`، `Pacman`، `Zypper`، `APK`

۲. فایل‌های نصب مستقل

دانلود و نصب بسته از وب‌سایت سازنده

`.deb`، `.rpm`، `.AppImage`، `.tar.gz`

۳. بسته‌های مستقل از توزیع

بسته‌بندی با وابستگی‌ها و قالب مشخص

`Flatpak`، `Snap`، `Nix`، `Guix`

۴. نصب از کد منبع و ابزارهای توسعه

برای نرم‌افزارهای تخصصی، کتابخانه‌ها و برنامه‌های توسعه

`make`، `CMake`، `Meson`، `pip`، `npm`، `Cargo`

۵. محیط‌های ایزوله و کانتینرها

برای برنامه‌های سروری، توسعه و اجرای نرم‌افزارهای مستقل

`Docker`، `Podman`، `Conda`، `venv`

نکته مهم: همه این روش‌ها جایگزین یکدیگر نیستند. برای مثال، `APT` مدیر بسته سیستم است، `Flatpak` برای توزیع برنامه‌های دسکتاپ طراحی شده و `pip` عمدتاً بسته‌های پایتون را مدیریت می‌کند.

## ۲. مدیران بسته (Package Managers)

مدیر بسته ابزاری است که نصب، حذف، به‌روزرسانی، بررسی وابستگی‌ها و معمولاً دریافت نرم‌افزار از مخازن را انجام می‌دهد.

### ۲.۱. خانواده Debian و Ubuntu

![대학생이 리눅스 우분투를 2년간 써보면서 (Ubuntu 22.04) — 쓰기 전에 생각하자](https://images.openai.com/static-rsc-4/bF59MORMZ4qphvtglvWGYgBa5ni09ANAlMmB55QUd-o9yFozSeAyRZhIul-Yhtc7SobhfLUU-4MCQriFsymzoz_2dAFJUCIsw9UYvm3azBeLxrfJ1rODldsoPSSI2YcYF7uQIgpvcbzob4CNfV8QIOZBpxwtKnhhXzgklJ4o9pM?purpose=inline)

APT و dpkg

توزیع‌های رایج: Ubuntu، Debian، Linux Mint، Pop!_OS و بسیاری از توزیع‌های مبتنی بر Debian.

APT ابزار اصلی نصب از مخازن است و dpkg برای کار با بسته‌های محلی با قالب `.deb` به کار می‌رود.

|عملیات|دستور|
|---|---|
|به‌روزرسانی فهرست بسته‌ها|`sudo apt update`|
|ارتقای بسته‌های نصب‌شده|`sudo apt upgrade`|
|نصب برنامه|`sudo apt install vlc`|
|حذف برنامه|`sudo apt remove vlc`|
|حذف برنامه و تنظیمات سیستمی آن|`sudo apt purge vlc`|
|پاک‌سازی وابستگی‌های غیرضروری|`sudo apt autoremove`|
|جست‌وجوی بسته|`apt search vlc`|
|مشاهده اطلاعات بسته|`apt show vlc`|
|فهرست بسته‌های نصب‌شده|`apt list --installed`|
|نصب فایل محلی DEB|`sudo apt install ./program.deb`|

مثال نصب یک بسته DEB با ابزار سطح پایین:

```
sudo dpkg -i program.deb
```

اگر وابستگی‌های بسته ناقص باشند، می‌توان در شرایط مناسب از دستور زیر برای رفع آن‌ها استفاده کرد:

```
sudo apt --fix-broken install
```

تفاوت مهم:
`apt` معمولاً وابستگی‌ها را از مخازن حل می‌کند، اما `dpkg` به‌تنهایی مدیر مخازن و حل‌کننده کامل وابستگی‌ها نیست.

### ۲.۲. خانواده Fedora، RHEL و توزیع‌های مبتنی بر RPM

![Fedora Icon & Logo (selfh.st) | Dashboard Icons & Logos](https://images.openai.com/static-rsc-4/Ua4NreUkWcbvNkF0_D0iQL1KTQDcRg_ORcf7On3SQn6xXz7pokQgywrqsNfvI3FxsIiIovqNDUqxDqbFD3jsmmzuxl98pLQFLMZTOfh8jlJRyBpuA2sYiKYcK2cq8wt-qqTw6GhioUMwCB4stjTyI4of_8Y3WZi9eNCXxDxKxxo?purpose=inline)

DNF، YUM و RPM

توزیع‌های رایج: Fedora، RHEL، Rocky Linux، AlmaLinux و نسخه‌های جدید CentOS Stream.

|عملیات|دستور|
|---|---|
|نصب برنامه|`sudo dnf install vlc`|
|حذف برنامه|`sudo dnf remove vlc`|
|به‌روزرسانی بسته‌ها|`sudo dnf upgrade`|
|جست‌وجو|`dnf search vlc`|
|مشاهده اطلاعات بسته|`dnf info vlc`|
|فهرست بسته‌های نصب‌شده|`dnf list installed`|
|نصب فایل RPM محلی|`sudo dnf install ./program.rpm`|
|مشاهده تاریخچه تراکنش‌ها|`dnf history`|

`YUM` نام مدیر بسته‌ای است که در نسخه‌های قدیمی‌تر RHEL و Fedora بسیار رایج بود. در نسخه‌های جدید، `DNF` ابزار اصلی است و در بعضی سیستم‌ها دستور `yum` همچنان به DNF متصل است.

ابزار سطح پایین RPM:

```
sudo rpm -ivh program.rpm
sudo rpm -Uvh program.rpm
sudo rpm -e package-name
```

- `-i`: نصب
    
- `-U`: نصب یا ارتقا
    
- `-e`: حذف
    

برای نصب بسته محلی، معمولاً `dnf install ./program.rpm` انتخاب مناسب‌تری است، زیرا می‌تواند وابستگی‌ها را از مخازن حل کند.

### ۲.۳. خانواده Arch Linux

![Arch Linux icon in Material Design style](https://images.openai.com/static-rsc-4/TyKHwyUwu7UCH7DuY_3TQ1C70jnwHpITNlXtZDKpsy5Xh3_7w1oBSU2NqHgRtetJ-QkZrltBfqtNqmznAj0Nwb6K7rHvrPwW7x2k6_x9JtU585RRF_HtuST4aQsg_096dYTQoNtxBgukvdUlJQNEK747QGDEeN_bRt3SnBppbPE?purpose=inline)

Pacman

توزیع‌های رایج: Arch Linux، EndeavourOS و Manjaro؛ البته تنظیمات مخازن و سیاست به‌روزرسانی ممکن است متفاوت باشد.

|عملیات|دستور|
|---|---|
|همگام‌سازی مخازن و ارتقای سیستم|`sudo pacman -Syu`|
|نصب برنامه|`sudo pacman -S vlc`|
|حذف برنامه|`sudo pacman -R vlc`|
|حذف برنامه و وابستگی‌های بدون استفاده|`sudo pacman -Rs vlc`|
|جست‌وجو در مخازن|`pacman -Ss vlc`|
|جست‌وجوی بسته نصب‌شده|`pacman -Qs vlc`|
|مشاهده اطلاعات بسته|`pacman -Si vlc`|
|فهرست بسته‌های نصب‌شده|`pacman -Q`|
|نصب بسته محلی|`sudo pacman -U program.pkg.tar.zst`|

در Arch معمولاً بهتر است به‌جای ارتقای جزئی بسته‌ها، ارتقای کامل سیستم با `sudo pacman -Syu` انجام شود؛ ارتقای ناقص می‌تواند باعث ناسازگاری بسته‌ها شود.

## ۳. نصب برنامه با Flatpak

![Flatpak Logo PNG,  Vector (AI, EPS, CDR, PDF, SVG) - iconLogoVector](https://images.openai.com/static-rsc-4/5arbhbcJMzfhb-cw8IMEHr0HaygxmWPFxBU4sVDbeDyFHqJRbm-3pPK9RFA38oPKnLCj_s8KJARr4U46HyDLV-G5itWCRsJHVxXZXpAIqX0r-7ruB9UhWXVR3KpAj9su3XKZbYm1NiTy9zn2tNRWQfIRjb1RnggAKvlBK5Jq-ro?purpose=inline)

Flatpak

روشی برای توزیع برنامه‌های دسکتاپ با محیط اجرای مشترک و امکان محدودکردن دسترسی برنامه‌ها به منابع سیستم.

Flatpak برای برنامه‌هایی مثل ویرایشگر تصویر، مرورگر، پخش‌کننده رسانه و ابزارهای گرافیکی بسیار مناسب است. یکی از مخازن شناخته‌شده آن Flathub است.

### نصب و راه‌اندازی در Ubuntu و Debian

ابتدا Flatpak را نصب کنید:

```
sudo apt update
sudo apt install flatpak
```

برای اضافه‌کردن مخزن Flathub:

```
flatpak remote-add --if-not-exists flathub \
https://dl.flathub.org/repo/flathub.flatpakrepo
```

سپس ترمینال یا نشست کاربری را در صورت نیاز دوباره راه‌اندازی کنید.

### دستورات مهم

|عملیات|دستور|
|---|---|
|جست‌وجوی برنامه|`flatpak search firefox`|
|نصب برنامه|`flatpak install flathub org.mozilla.firefox`|
|اجرای برنامه|`flatpak run org.mozilla.firefox`|
|فهرست برنامه‌های نصب‌شده|`flatpak list`|
|به‌روزرسانی همه برنامه‌ها|`flatpak update`|
|حذف برنامه|`flatpak uninstall org.mozilla.firefox`|
|حذف وابستگی‌های بلااستفاده|`flatpak uninstall --unused`|
|مشاهده مخازن|`flatpak remotes`|

شناسه برنامه‌ها مانند `org.mozilla.firefox` را می‌توان در صفحه همان برنامه در Flathub پیدا کرد.

مزیت‌ها: نسخه‌های نسبتاً مستقل از توزیع، جداسازی نسبی برنامه‌ها و مناسب‌بودن برای دسکتاپ.

محدودیت‌ها: مصرف فضای بیشتر در برخی موارد، نیاز به مدیریت مجوزها و احتمال تفاوت در یکپارچگی تم‌ها یا دسترسی به فایل‌ها.

## ۴. نصب برنامه با Snap

![An Introduction to the Snap Universal Package Manager - The New Stack](https://images.openai.com/static-rsc-4/EOpo-dm0Bmsdc5kJLheeahkSfE6hDzv8S_Q_CQg73VNm0sfWxaaaCmp0wMCxeCdUO_D8OUoMBRuk_2_uLJqXL5veeLZdNVTYnjp_La6eaqZMdHahGooV6_ECIn7Frq5vvszbB61A1-pHMmcoJEwzvWwAb8i4CIFlSbpasUGzIX4?purpose=inline)

Snap

سیستم بسته‌بندی نرم‌افزار همراه با سرویس `snapd` که به‌ویژه در Ubuntu کاربرد دارد.

### نصب و راه‌اندازی

در توزیع‌هایی که Snap را به‌صورت پیش‌فرض ندارند، در صورت پشتیبانی:

```
sudo apt update
sudo apt install snapd
```

برای مثال نصب Firefox در سیستمی که Snap و مخزن مربوطه را پشتیبانی می‌کند:

```
sudo snap install firefox
```

### دستورات اصلی

|عملیات|دستور|
|---|---|
|جست‌وجو|`snap find firefox`|
|نصب|`sudo snap install firefox`|
|حذف|`sudo snap remove firefox`|
|فهرست برنامه‌ها|`snap list`|
|به‌روزرسانی|`sudo snap refresh`|
|به‌روزرسانی یک برنامه|`sudo snap refresh firefox`|
|مشاهده اطلاعات|`snap info firefox`|
|بررسی اتصال‌های دسترسی|`snap connections firefox`|

برای دیدن کانال‌های انتشار برنامه:

```
snap info firefox
```

بعضی برنامه‌ها کانال‌های `stable`، `candidate`، `beta` و `edge` دارند. انتخاب کانال‌های آزمایشی ممکن است نسخه‌های ناپایدار نصب کند.

مزیت‌ها: به‌روزرسانی خودکار، انتشار نسخه‌های جدید و محدودسازی دسترسی‌ها.

محدودیت‌ها: نیاز به `snapd`، مصرف فضای بیشتر در بعضی شرایط و تفاوت تجربه کاربری در توزیع‌های مختلف.

## ۵. مقایسه APT، DNF، Pacman، Flatpak و Snap

|ویژگی|APT / DNF / Pacman|Flatpak|Snap|
|---|---|---|---|
|هدف اصلی|بسته‌های سیستم و برنامه‌ها|برنامه‌های دسکتاپ|برنامه‌های دسکتاپ و برخی سرویس‌ها|
|وابستگی به توزیع|زیاد|کمتر|کمتر|
|دریافت از مخزن|بله|بله|بله|
|مدیریت وابستگی‌ها|بله|از طریق Runtime و بسته‌ها|در قالب Snap و محیط اجرای آن|
|به‌روزرسانی خودکار|بسته به سیستم و تنظیمات|معمولاً با دستور یا ابزار گرافیکی|معمولاً به‌صورت خودکار|
|نیاز به سرویس ویژه|معمولاً خیر|برای قابلیت‌های اصلی خیر|معمولاً بله، `snapd`|
|مناسب برای|نرم‌افزارهای سیستمی و یکپارچگی بالا|اپلیکیشن‌های گرافیکی چندتوزیعی|اپلیکیشن‌های بسته‌بندی‌شده|

قاعده پیشنهادی:

- ابزارهای سیستمی، کتابخانه‌ها و بسته‌های توزیع: ابتدا مخازن رسمی.
    
- برنامه دسکتاپ با نسخه نسبتاً مستقل از توزیع: Flatpak گزینه خوبی است.
    
- برنامه‌ای که سازنده آن را از طریق Snap منتشر می‌کند: Snap گزینه مناسبی است.
    
- اگر برنامه در مخزن رسمی نسخه مناسب و پشتیبانی‌شده‌ای دارد، معمولاً لازم نیست بدون دلیل سراغ چند روش مختلف بروید.
    

## ۶. نصب برنامه با AppImage

![GitHub - AppImage/AppImageKit: Package desktop applications as AppImages that run on common Linux-based operating systems, such as RHEL, CentOS, openSUSE, SLED, Ubuntu, Fedora, debian and derivatives. Join #AppImage on irc.libera.chat](https://images.openai.com/static-rsc-4/IlN13xPmKk7NNkMIFMnIWgIIU6iDTob-Kq9IczeKfb_cXcqiiln184hAuyMKwVD0i07xudXr5A0jqaJ2Enrr0kBkMBvs6HWR4MUtJP0I_3JodKzHqmMNNhuWY3ErQ2VGAFIla6IMG1lb9ayNJb1ZdJslSPgzWwKRbtOwD0R1KTk?purpose=inline)

AppImage

قالبی برای توزیع بسیاری از برنامه‌های لینوکس در یک فایل اجرایی؛ معمولاً بدون نصب سنتی در مدیر بسته.

برای مثال، اگر فایل برنامه `MyApp.AppImage` را از منبع معتبر دریافت کرده‌اید:

```
chmod +x MyApp.AppImage
./MyApp.AppImage
```

برای اجرا در دفعات بعد کافی است فایل را اجرا کنید. در صورت نیاز می‌توانید آن را در پوشه‌ای مانند `~/Applications` نگه دارید.

نکات مهم:

- AppImage الزاماً شامل همه کتابخانه‌ها و وابستگی‌های لازم نیست.
    
- ممکن است برای اجرا به FUSE یا سازگاری با کتابخانه‌های سیستم نیاز داشته باشد.
    
- یکپارچگی با منو، به‌روزرسانی و حذف برنامه به روش توزیع‌کننده وابسته است.
    
- برای حذف معمولاً حذف فایل و فایل‌های تنظیمات مرتبط کافی است؛ البته اطلاعات کاربر ممکن است جداگانه ذخیره شده باشد.
    

AppImage معمولاً مدیر بسته مرکزی سیستم را برای نصب و حذف برنامه به کار نمی‌گیرد.

## ۷. نصب از فایل‌های DEB و RPM

این روش وقتی کاربرد دارد که سازنده برنامه فایل نصب مخصوص توزیع شما را ارائه کرده باشد.

### فایل DEB

برای Debian، Ubuntu و توزیع‌های سازگار:

```
sudo apt install ./program.deb
```

یا در سطح پایین‌تر:

```
sudo dpkg -i program.deb
```

### فایل RPM

برای Fedora و توزیع‌های سازگار:

```
sudo dnf install ./program.rpm
```

### بررسی معماری سیستم

پیش از دانلود، معماری سیستم را بررسی کنید:

```
uname -m
```

خروجی‌های رایج:

- `x86_64`: سیستم‌های ۶۴ بیتی مبتنی بر x86
    
- `aarch64`: سیستم‌های ARM با معماری ۶۴ بیتی
    
- `i686`: سیستم‌های قدیمی‌تر ۳۲ بیتی x86
    

هشدار: نصب فایل مخصوص توزیع دیگر ممکن است باعث ناسازگاری وابستگی‌ها شود. فایل DEB را صرفاً به این دلیل که نصب آن امکان‌پذیر است روی Fedora یا فایل RPM را روی Ubuntu نصب نکنید.

## ۸. نصب از آرشیوهای ZIP، TAR، TAR.GZ و TAR.XZ

همه فایل‌هایی که از وب‌سایت‌ها دریافت می‌کنید، بسته نصب نیستند. برخی فقط آرشیو فایل‌ها، نسخه قابل‌حمل یا کد منبع هستند.

### استخراج آرشیوها

```
unzip program.zip
tar -xf program.tar
tar -xzf program.tar.gz
tar -xJf program.tar.xz
```

اگر آرشیو را نمی‌شناسید، ابتدا نوع آن را بررسی کنید:

```
file program.tar.gz
```

پس از استخراج، فایل‌های داخل پوشه را بررسی کنید:

```
ls -la
```

ممکن است با یکی از این حالت‌ها روبه‌رو شوید:

- فایل اجرایی آماده
    
- اسکریپت نصب مانند `install.sh`
    
- کد منبع با فایل‌هایی مانند `configure` یا `CMakeLists.txt`
    
- راهنمای نصب در `README` یا `INSTALL`
    

مهم: هر فایل `install.sh` یا `setup.sh` را بدون بررسی اجرا نکنید. این اسکریپت‌ها می‌توانند تغییرات گسترده‌ای در سیستم ایجاد کنند.

## ۹. نصب از کد منبع (Source Code)

این روش برای نرم‌افزارهایی مناسب است که فایل اجرایی آماده ندارند یا می‌خواهید خودتان آن‌ها را کامپایل کنید.

### ۹.۱. روش کلاسیک Autotools

ابتدا ابزارهای کامپایل را نصب کنید. برای Ubuntu و Debian:

```
sudo apt update
sudo apt install build-essential autoconf automake libtool pkg-config
```

سپس در پوشه کد منبع:

```
./configure
make
```

برای نصب سراسری، اگر مستندات پروژه همین روش را توصیه می‌کنند:

```
sudo make install
```

توجه کنید که این فقط یک الگوی عمومی است؛ همه پروژه‌ها فایل `configure` ندارند.

### ۹.۲. روش CMake

نصب ابزارها:

```
sudo apt install build-essential cmake
```

کامپایل:

```
cmake -S . -B build
cmake --build build
```

نصب در صورت نیاز:

```
sudo cmake --install build
```

مسیر نصب به تنظیمات پروژه وابسته است. برای جلوگیری از تداخل با بسته‌های توزیع، در پروژه‌های شخصی می‌توان از مسیرهای جداگانه استفاده کرد.

### ۹.۳. روش Meson و Ninja

```
sudo apt install meson ninja-build build-essential
```

سپس:

```
meson setup build
meson compile -C build
```

اگر پروژه نصب را پشتیبانی می‌کند:

```
sudo meson install -C build
```

### ۹.۴. ابزارهای تخصصی ساخت نرم‌افزار

|ابزار|کاربرد|
|---|---|
|`make`|اجرای دستورهای تعریف‌شده در Makefile|
|`CMake`|پیکربندی و تولید فایل‌های ساخت|
|`Meson`|سیستم ساخت مدرن|
|`Ninja`|اجرای سریع عملیات ساخت|
|`Autotools`|مجموعه ابزارهای سنتی ساخت نرم‌افزار|
|`gcc` / `g++`|کامپایلرهای C و C++|
|`clang`|کامپایلر خانواده LLVM|
|`checkinstall`|ساخت بسته در برخی گردش‌کارهای قدیمی؛ محدودیت‌ها و سازگاری آن باید بررسی شود|

مزایا: کنترل بیشتر بر نسخه، گزینه‌های کامپایل و قابلیت‌های برنامه.

معایب: نیاز به دانش فنی، مدیریت دستی وابستگی‌ها و احتمال دشوارترشدن حذف و به‌روزرسانی.

به‌طور کلی، نصب از کد منبع باید انتخابی آگاهانه باشد، نه جایگزین همیشگی مخازن رسمی.

## ۱۰. مدیران بسته زبان‌های برنامه‌نویسی

این دسته با مدیر بسته سیستم متفاوت است. معمولاً برای نصب کتابخانه‌ها، ابزارهای توسعه و وابستگی‌های یک پروژه استفاده می‌شوند.

### ۱۰.۱. Python و ابزارهای آن

|ابزار|کاربرد|
|---|---|
|`pip`|نصب بسته‌های پایتون|
|`venv`|ایجاد محیط مجازی پایتون|
|`pipx`|نصب برنامه‌های خط فرمان پایتونی در محیط‌های جداگانه|
|`uv`|مدیریت سریع محیط‌ها، وابستگی‌ها و پروژه‌های پایتون|
|`Conda`|مدیریت محیط و بسته‌ها، به‌ویژه در علم داده|
|`Poetry`|مدیریت وابستگی و پروژه پایتون|

روش پیشنهادی برای یک پروژه پایتون:

```
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests
```

پس از پایان کار:

```
deactivate
```

برای نصب یک برنامه خط فرمان پایتونی با `pipx`، ابتدا باید آن را از روش مناسب توزیع خود نصب کرده باشید؛ سپس:

```
pipx install httpie
```

بهتر است از نصب مستقیم بسته‌های Python با دسترسی مدیریتی در محیط سراسری سیستم خودداری کنید. در برخی توزیع‌های جدید، محیط Python سیستم برای مدیریت توسط مدیر بسته محافظت شده است.

### ۱۰.۲. JavaScript و Node.js

|ابزار|کاربرد|
|---|---|
|`npm`|مدیر بسته پیش‌فرض Node.js|
|`pnpm`|مدیر بسته با مدیریت کارآمد فضای ذخیره‌سازی|
|`Yarn`|مدیر بسته JavaScript|
|`nvm`|مدیریت نسخه‌های Node.js برای هر کاربر|
|`Corepack`|مدیریت نسخه مدیران بسته پشتیبانی‌شده در نسخه‌های سازگار Node.js|

نمونه:

```
npm install
npm install lodash
npm install -g typescript
```

برای نصب وابستگی‌های پروژه، دستور `npm install` را در پوشه‌ای که فایل `package.json` دارد اجرا کنید. نصب سراسری به روش نصب Node.js و مجوزهای سیستم وابسته است.

### ۱۰.۳. زبان‌های دیگر

|زبان یا اکوسیستم|ابزار|مثال|
|---|---|---|
|Rust|Cargo|`cargo install ripgrep`|
|Go|Go toolchain|`go install example.com/tool@latest`|
|Ruby|RubyGems / Bundler|`gem install bundler`|
|PHP|Composer|`composer install`|
|Java|Maven / Gradle|`mvn package`|
|.NET|NuGet / dotnet CLI|`dotnet tool install`|
|R|`install.packages()`|نصب بسته از محیط R|
|Perl|CPAN / cpanm|نصب ماژول Perl|

این ابزارها برای مدیریت بسته‌های زبان یا ساخت برنامه کاربرد دارند؛ جایگزین کامل مدیر بسته سیستم نیستند.

## ۱۲. مخازن رسمی، مخازن جانبی و منابع ثالث

مخزن (Repository) مجموعه‌ای از بسته‌ها و اطلاعات آن‌هاست که مدیر بسته از آن دریافت می‌کند.

### انواع مخازن

1. مخزن رسمی توزیع: معمولاً مطمئن‌ترین نقطه شروع برای نصب برنامه‌ها.
    
2. مخزن رسمی سازنده نرم‌افزار: مثلاً مخزن اختصاصی یک شرکت برای توزیع بسته‌های خودش.
    
3. مخزن جانبی: مانند PPA در Ubuntu یا COPR در Fedora.
    
4. مخزن جامعه کاربری: مانند AUR در Arch Linux.
    
5. مخزن Flatpak: مانند Flathub.
    
6. فروشگاه Snap: کاتالوگ بسته‌های Snap.
    
7. مخزن محلی یا سازمانی: برای شبکه‌های داخلی، محیط‌های بدون اینترنت و مدیریت متمرکز.
    

### ابزارهای ویژه مدیریت مخازن

|ابزار یا مفهوم|کاربرد|
|---|---|
|`add-apt-repository`|مدیریت برخی مخازن اضافی در Ubuntu و سیستم‌های سازگار|
|PPA|مخزن شخص ثالث برای سیستم‌های مبتنی بر Ubuntu|
|COPR|ساخت و انتشار بسته‌های Fedora توسط کاربران و توسعه‌دهندگان|
|AUR|مجموعه دستورهای ساخت بسته برای Arch Linux|
|`zypper addrepo`|افزودن مخزن در openSUSE|
|`dnf config-manager`|مدیریت مخازن در نسخه‌های سازگار DNF|
|`flatpak remote-add`|افزودن منبع Flatpak|
|`snap`|نصب و مدیریت Snapها از فروشگاه و کانال‌های انتشار|

نمونه افزودن PPA در Ubuntu:

```
sudo add-apt-repository ppa:OWNER/PPA
sudo apt update
```

در این مثال، `OWNER/PPA` فقط جای‌نگهدار است و باید با مخزن واقعی و معتبر جایگزین شود.

هشدار مهم: مخزن ثالث می‌تواند بسته‌های سیستمی را جایگزین یا نسخه‌های ناسازگار نصب کند. تنها مخازنی را اضافه کنید که به منبع و نگه‌داری آن‌ها اعتماد دارید.

این دو ابزار برای اجرای برنامه‌ها در کانتینر استفاده می‌شوند. کانتینر یک محیط اجرای جداشده فراهم می‌کند، اما برخلاف ماشین مجازی معمولاً هسته سیستم میزبان را به اشتراک می‌گذارد.

Docker

مناسب اجرای سرویس‌های وب، پایگاه داده، محیط‌های توسعه و برنامه‌های سروری.

![Introduction to Podman: An alternative to Docker?](https://images.openai.com/static-rsc-4/kmfAl1idT-1vJBnnn6X891gfs6El5FgIcJt5nJfv9jeR2H1pnoboeOGS28oedlFlVQsn8H8uvNmpD5l86vrR_VO0wrFgwl3JtC4PZ1_HlWE1O47oHSEOBZDmEFejCPbtl7lAZL419oxzWVJJLosuj_M_pb0En5huR22jlhVhGO8?purpose=inline)

Podman

ابزار اجرای کانتینر که از اجرای بدون دسترسی ریشه نیز پشتیبانی می‌کند و در بسیاری از کاربردها جایگزین Docker است.

### دستورات پرکاربرد Docker

```

docker run -d --name web -p 8080:80 nginx
docker ps
docker logs web
docker stop web
docker rm web

```

این مثال یک وب‌سرور Nginx را در کانتینر اجرا می‌کند. پس از اجرا، در صورت دسترسی به میزبان، سرویس از طریق پورت ۸۰۸۰ در دسترس است.

### دستورات مشابه در Podman

```
podman pull nginx
podman run -d --name web -p 8080:80 nginx
podman ps
podman stop web
podman rm web
```

چه زمانی از کانتینر استفاده کنیم؟

- برای برنامه‌های سروری و APIها.
    
- برای پایگاه داده‌ای که نمی‌خواهید مستقیماً در سیستم نصب کنید.
    
- برای محیط توسعه قابل‌بازتولید.
    
- برای آزمایش نسخه‌های مختلف یک نرم‌افزار.
    

کانتینر جایگزین مناسبی برای همه برنامه‌های دسکتاپ نیست؛ همچنین داده‌های مهم باید با Volume یا روش پایدار دیگری ذخیره شوند.

## ۱۴. نصب ابزارهای خط فرمان و فایل‌های اجرایی مستقل

برخی برنامه‌ها مدیر بسته اختصاصی ندارند و فقط یک فایل اجرایی منتشر می‌کنند.

### ۱۴.۱. نصب در مسیر کاربر

برای ابزارهای شخصی، مسیرهایی مانند این مناسب‌اند:

```
mkdir -p ~/.local/bin
```

اگر فایل اجرایی را در این مسیر قرار دهید، می‌توانید آن را بدون دسترسی مدیر سیستم اجرا کنید. برای دسترسی راحت‌تر باید `~/.local/bin` در متغیر `PATH` باشد.

بررسی `PATH`:

```
echo "$PATH"
```

### ۱۴.۲. نصب سراسری

در بسیاری از سیستم‌ها، برنامه‌های اجرایی شخصی یا مدیریتی در مسیرهایی مانند این قرار می‌گیرند:

- `/usr/bin`
    
- `/usr/local/bin`
    
- `/opt`
    

این مسیرها کاربردهای یکسانی ندارند. معمولاً فایل‌های متعلق به بسته‌های توزیع در `/usr` و نرم‌افزارهای نصب‌شده به‌صورت محلی در `/usr/local` قرار می‌گیرند؛ `/opt` نیز برای بعضی نرم‌افزارهای مستقل مناسب است.

از کپی‌کردن تصادفی فایل‌ها در `/usr/bin` خودداری کنید، زیرا ممکن است با بسته‌های سیستم تداخل ایجاد شود.

### ۱۴.۳. مدیریت برنامه‌های نصب‌شده در `/opt`

بعضی نرم‌افزارهای تجاری یا ابزارهای توسعه در پوشه اختصاصی خود نصب می‌شوند:

```
/opt/example-app/
```

این روش زمانی مفید است که برنامه ساختار نصب مستقل دارد. برای اینکه برنامه از منو اجرا شود، ممکن است نیاز به فایل `.desktop` داشته باشید.

## ۱۵. ابزارهای پیشرفته مدیریت نسخه و محیط

این ابزارها برای کاربران حرفه‌ای، توسعه‌دهندگان و کسانی که به نسخه‌های متعدد یک برنامه نیاز دارند، مفیدند.

|ابزار|کاربرد اصلی|
|---|---|
|Nix|نصب بسته‌ها در محیط‌های مجزا و تعریف‌پذیر|
|GNU Guix|مدیریت بسته و محیط‌های بازتولیدپذیر|
|Spack|مدیریت نرم‌افزارهای علمی و محاسباتی|
|Environment Modules|انتخاب نسخه ابزارها در سرورها و محیط‌های علمی|
|Lmod|مدیریت محیط‌های ماژولار در محاسبات علمی|
|asdf|مدیریت چند نسخه از زبان‌ها و ابزارهای توسعه|
|mise|مدیریت نسخه ابزارهای توسعه|
|pyenv|مدیریت نسخه‌های Python|
|nvm|مدیریت نسخه‌های Node.js|
|rustup|مدیریت ابزارها و نسخه‌های Rust|

### نمونه استفاده از Nix

پس از نصب و راه‌اندازی Nix به روش مستندشده برای توزیع خود:


Nix علاوه بر نصب نرم‌افزار، قابلیت ساخت محیط‌های توسعه بازتولیدپذیر را نیز فراهم می‌کند.

### نمونه محیط موقت توسعه

در بعضی پروژه‌ها می‌توانید به‌جای نصب دائمی ابزارها، محیط توسعه تعریف کنید. برای مثال با Nix:

```
nix shell nixpkgs#git nixpkgs#ripgrep
```

پس از پایان محیط، ابزارها لزوماً از پروفایل دائمی شما حذف نمی‌شوند، اما دیگر در همان نشست موقت در دسترس نخواهند بود.

## ۱۶. اسکریپت‌های نصب و ابزارهای خودکار

برخی پروژه‌ها نصب را با یک اسکریپت Shell انجام می‌دهند:

```
bash install.sh
```

یا:

```
./install.sh
```

این روش ممکن است برای ابزارهای توسعه، محیط‌های برنامه‌نویسی و نرم‌افزارهای تخصصی استفاده شود.

با این حال، اسکریپت نصب یک مدیر بسته نیست و ممکن است بسته‌ها را دانلود کند، فایل‌ها را تغییر دهد، سرویس بسازد یا تنظیمات امنیتی را تغییر دهد.

پیش از اجرای آن:

```
less install.sh
```

برای پیدا کردن دستورات حساس می‌توانید جست‌وجو کنید:

```
grep -nE 'sudo|curl|wget|rm -rf|chmod|chown' install.sh
```

این جست‌وجو فقط یک بررسی اولیه است و امنیت اسکریپت را تضمین نمی‌کند.

روش مناسب‌تر، در صورت وجود، استفاده از بسته رسمی، بررسی امضای دیجیتال یا checksum و پیروی از راهنمای معتبر سازنده است.

## ۱۷. نصب برنامه‌های اندرویدی و ویندوزی در لینوکس

این روش‌ها با نصب معمول برنامه‌های بومی لینوکس تفاوت دارند.

### برنامه‌های اندرویدی

ابزارهایی مانند Waydroid و محیط‌های سازگار دیگر، اجرای برخی برنامه‌های Android را روی لینوکس ممکن می‌کنند. سازگاری به توزیع، کرنل، محیط گرافیکی و نیازهای برنامه وابسته است.

### برنامه‌های ویندوزی

- Wine: اجرای بسیاری از برنامه‌های ویندوز بدون نیاز به نصب کامل ویندوز.
    
- Bottles: مدیریت محیط‌های Wine با تنظیمات جداگانه.
    
- Lutris: مدیریت و اجرای بازی‌ها و نرم‌افزارهای مختلف.
    
- Proton: لایه سازگاری مبتنی بر Wine که به‌ویژه در Steam برای بازی‌ها استفاده می‌شود.
    
- ماشین مجازی: اجرای ویندوز کامل با ابزارهایی مانند KVM/QEMU یا VirtualBox.
    

هیچ‌یک از این روش‌ها تضمین نمی‌کند که همه برنامه‌های ویندوزی به‌درستی اجرا شوند.

## ۱۸. چگونه بفهمیم کدام روش برای سیستم ما مناسب است؟

ابتدا توزیع لینوکس و نسخه آن را بررسی کنید:

```
cat /etc/os-release
uname -m
```

سپس از جدول زیر استفاده کنید.

|توزیع|روش پیش‌فرض پیشنهادی|روش‌های مکمل|
|---|---|---|
|Ubuntu|APT|Flatpak، Snap، DEB|
|Debian|APT|Flatpak، AppImage|
|Linux Mint|APT|Flatpak، بسته‌های سازگار|
|Fedora|DNF|Flatpak، RPM|
|Arch Linux|Pacman|AUR با احتیاط، Flatpak|
|Manjaro|Pacman از طریق ابزارهای توزیع|Pamac، Flatpak|
|openSUSE|Zypper|Flatpak، RPM|
|Alpine Linux|APK|کانتینرها و ابزارهای سازگار|
|NixOS|Nix و تنظیمات اعلامی سیستم|Flatpak یا روش‌های سازگار با پیکربندی|

این جدول راهنمای عمومی است؛ بعضی توزیع‌ها تنظیمات ویژه‌ای دارند و ممکن است همه گزینه‌ها را به‌صورت پیش‌فرض فعال نکنند.

## ۱۹. دستورات عمومی برای مدیریت نرم‌افزار

این دستورات مستقل از مدیر بسته خاصی نیستند، اما برای شناخت سیستم و بررسی وضعیت نرم‌افزارها بسیار کاربردی‌اند.

|هدف|دستور|
|---|---|
|شناسایی توزیع|`cat /etc/os-release`|
|شناسایی معماری|`uname -m`|
|پیدا کردن محل یک دستور|`command -v firefox`|
|بررسی مسیر فایل اجرایی|`which firefox`|
|نمایش اطلاعات فایل|`file program`|
|بررسی وابستگی‌های ELF|`ldd ./program`|
|مشاهده فضای دیسک|`df -h`|
|مشاهده حجم پوشه‌ها|`du -sh ~/Applications`|
|بررسی فرایند اجرا|`ps aux`|
|بررسی متغیر PATH|`echo "$PATH"`|

احتیاط: `ldd` را روی فایل اجرایی ناشناس و غیرقابل‌اعتماد اجرا نکنید؛ برای بررسی فایل‌های مشکوک بهتر است از ابزارهای ایمن‌تر مانند `readelf` استفاده کنید.

## ۲۰. نکات امنیتی مهم هنگام نصب

اولویت با مخازن معتبر

بسته‌های مخازن رسمی معمولاً با سیستم بسته‌بندی توزیع یکپارچه‌اند و به‌روزرسانی آن‌ها آسان‌تر است.

اجرای دستورهای اینترنتی با `sudo`

دستورهایی مانند `curl ... | sudo bash` را بدون بررسی منبع و محتوای اسکریپت اجرا نکنید.

بررسی امضا و checksum

در صورت ارائه توسط سازنده، امضای دیجیتال و checksum را از منبع معتبر بررسی کنید.

پیش از حذف یا ارتقای عمده پشتیبان بگیرید

در سیستم‌های سروری و سیستم‌های حیاتی، ابتدا تأثیر عملیات و وابستگی‌ها را بررسی کنید.
