## 1. Overview

**Docker Engine** is the core technology that allows you to build and run containers.

When you type commands such as:

```bash
docker run nginx
```

Docker Engine is responsible for making that happen.

A simplified model is:

```text
You
 ↓
Docker CLI
 ↓
Docker Engine
 ↓
Container
```

Docker Engine manages the underlying Docker resources needed to run containers.

---

# 2. What Does Docker Engine Do?

Docker Engine provides the functionality needed to:

- Build container images
    
- Run containers
    
- Stop containers
    
- Remove containers
    
- Manage images
    
- Manage networks
    
- Manage volumes
    
- Communicate with registries
    
- Control container resources
    

Think of Docker Engine as the **main engine behind Docker**.

# 5. Docker CLI

The **Docker CLI** is the command-line interface.

You interact with Docker using commands such as:

```bash
docker ps
```

```bash
docker images
```

```bash
docker run nginx
```

The CLI sends requests to the Docker daemon.

```text
Docker CLI
    │
    ↓
Docker API
    │
    ↓
Docker Daemon
```

---

# 6. Docker Daemon

The Docker daemon is called:

```text
dockerd
```

It runs as a background service.

Its job is to manage Docker objects and operations.

For example:

```text
dockerd
 │
 ├── Containers
 ├── Images
 ├── Networks
 └── Volumes
```

When you execute:

```bash
docker run nginx
```

the daemon receives the request and performs the necessary work.

---

# 7. Docker API

The Docker API provides communication between the client and daemon.

```text
Docker CLI
     │
     │ API request
     ↓
Docker Daemon
```

This means Docker can be controlled by more than just the command line.

Software can communicate with Docker programmatically through the API.

---

# 8. Container Runtime

The container runtime is responsible for the lower-level work required to create and run containers.

Modern Docker Engine uses **containerd** as an important component of its container runtime architecture.

Simplified:

```text
Docker CLI
     ↓
Docker Daemon
     ↓
containerd
     ↓
Container
```

At an even lower level, components such as **runc** are involved in creating and running containers according to the OCI container runtime specifications.

For beginner-level Docker learning, remember:

```text
dockerd
   ↓
containerd
   ↓
runc
   ↓
Container Process
```

This is a simplified conceptual model rather than a complete implementation diagram.

# 10. Docker Engine vs Docker Desktop

These names can be confusing.

## Docker Engine

Docker Engine is the core technology for running and managing containers.

On Linux, you can install and use Docker Engine directly.

## Docker Desktop

Docker Desktop is a desktop application that bundles Docker functionality with additional developer tools and a graphical interface.

It is commonly used on Windows and macOS and is also available for Linux.

For your Debian learning environment, you are primarily interested in:

```text
Docker Engine
```

rather than needing Docker Desktop.

---

# 11. Docker Engine vs Docker CLI

These are not the same thing.

### Docker CLI

The command you type:

```bash
docker
```

### Docker Engine

The underlying Docker system that processes the requests.

Think:

```text
You
 ↓
docker command
 ↓
Docker CLI
 ↓
Docker Engine / Daemon
 ↓
Container
```

For example:

```bash
docker ps
```

The CLI sends the request, and the daemon provides the container information.

---

# 12. Docker Engine vs Docker Daemon

These terms are related but should not be treated as exact synonyms.

### Docker Engine

The broader container-engine technology.

### Docker Daemon

The background service:

```text
dockerd
```

The daemon is a central component of Docker Engine.

Simplified:

```text
Docker Engine
│
├── Docker CLI
├── Docker API
├── Docker Daemon
└── Runtime components
```

# 13. What Happens During `docker run`?

Let's examine:

```bash
docker run nginx
```

### Step 1

You enter:

```bash
docker run nginx
```

### Step 2

The Docker CLI receives the command.

```text
Docker CLI
```

### Step 3

The CLI communicates with the Docker daemon.

```text
Docker CLI
    ↓
Docker API
    ↓
dockerd
```

### Step 4

The daemon checks whether the `nginx` image is available locally.

```text
Is nginx image available?
        │
     ┌──┴──┐
    Yes    No
     │      │
     │      ↓
     │   Pull image
     │      │
     └──────┘
        ↓
Create container
```

### Step 5

Docker creates the container.

```text
nginx Image
     ↓
nginx Container
```

### Step 6

The container runtime starts the container process.

```text
dockerd
   ↓
containerd
   ↓
runc
   ↓
nginx process
```

# 20. Docker Engine and Linux Kernel

Containers depend heavily on Linux kernel features.

Important concepts include:

- Namespaces
    
- Control groups (cgroups)
    
- Capabilities
    
- Linux filesystem features
    
- Networking features
    

These provide mechanisms for process isolation and resource management.

Simplified:

```text
Docker
  ↓
Linux Kernel
  ↓
Isolation + Resource Control
  ↓
Containers
```

You do not need to master Linux kernel internals yet.

Just remember:

> Docker containers rely on operating-system features to isolate and manage processes.

# 23. Check the Docker Service

On Debian Linux:

```bash
systemctl status docker
```

You may see:


# 24. Check the Docker Daemon Process

You can search for the daemon:

```bash
ps aux | grep dockerd
```

You may see a process containing:

```text
/usr/bin/dockerd
```

Do not worry if the exact command line differs between installations.

---

# 25. Check Docker Components

You can inspect Docker-related processes with:

```bash
ps aux | grep -E 'dockerd|containerd'
```

You may see processes such as:

```text
dockerd
containerd
```

Again, the exact output can vary by Docker version and installation.
