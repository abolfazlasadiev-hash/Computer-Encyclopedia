## 1. Overview

**Docker CLI** means **Docker Command-Line Interface**.

It is the command-line tool you use to communicate with Docker.

The command is:

```bash
docker
```

For example:

```bash
docker ps
```

You use the Docker CLI to:

- Run containers
    
- Stop containers
    
- Start containers
    
- Remove containers
    
- Download images
    
- Build images
    
- Manage networks
    
- Manage volumes
    
- View logs
    
- Inspect Docker objects
    

---

# 6. Command Structure

A Docker command generally looks like:

```text
docker [COMMAND] [OPTIONS] [ARGUMENTS]
```

Example:

```bash
docker run --name my-nginx nginx
```

Break it down:

```text
docker
  ↓
run
  ↓
--name my-nginx
  ↓
nginx
```

Meaning:

```text
docker
    → Docker CLI

run
    → Create and start a container

--name my-nginx
    → Give the container a name

nginx
    → Image to use
```

# 7. Commands and Options

Docker commands can have options.

Example:

```bash
docker ps -a
```

Here:

```text
docker
  ↓
ps
  ↓
-a
```

`-a` is an option.

Another example:

```bash
docker run --name my-nginx nginx
```

Here:

```text
--name
```

is an option.

And:

```text
my-nginx
```

is its value.

---

# 8. Short and Long Options

Docker often supports short and long forms.

Example:

```bash
docker ps -a
```

is the short form.

You can also use:

```bash
docker ps --all
```

These mean the same thing.

Another example:

```bash
docker run -d nginx
```

`-d` means detached mode.

# 14. Running a Container

One of the most important Docker CLI commands is:

```bash
docker run nginx
```

This tells Docker to create and start a container from the `nginx` image.

The general form is:

```bash
docker run IMAGE
```

Example:

```bash
docker run nginx
```

---

# 15. Running in Detached Mode

You can run a container in the background:

```bash
docker run -d nginx
```

The `-d` option means:

```text
detached
```

Docker starts the container and returns control of your terminal to you.

Check it:

```bash
docker ps
```

---

# 16. Naming Containers

You can give a container a meaningful name.

```bash
docker run -d --name my-nginx nginx
```

Now:

```bash
docker ps
```

can show:

```text
NAMES
my-nginx
```

This is easier than working with a randomly generated container name.

---

# 17. Publishing Ports

Containers have their own network environment.

To make a container service accessible through the host, you can publish a port.

Example:

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

The format is:

```text
-p HOST_PORT:CONTAINER_PORT
```

So:

```text
8080:80
```

means:

```text
Host port 8080
       ↓
Container port 80
```

You can then access the Nginx service through the host's port 8080.

Restart:

```bash

```

---

# 22. Removing a Container

Remove a stopped container:

```bash
docker rm my-nginx
```

Then:

```bash
docker ps -a
```

The container should no longer appear.

Important:

```text
docker stop
    ↓
Stops container

docker rm
    ↓
Removes container
```

Stopping does not automatically remove the container.

# 23. Viewing Logs

You can see a container's output using:

```bash
docker logs my-nginx
```

Follow logs continuously:

```bash
docker logs -f my-nginx
```

`-f` means follow.

Press:

```text
Ctrl + C
```

to stop following the output.

---

# 24. Executing Commands Inside a Container

You can execute a command inside a running container.

Example:

```bash
docker exec my-nginx nginx -v
```

For an interactive shell:

```bash
docker exec -it my-nginx bash
```

If the image doesn't contain Bash, try:

```bash
docker exec -it my-nginx sh
```

The options mean:

```text
-i
interactive

-t
allocate a terminal
```

Together:

```bash
-it
```

are commonly used for interactive shell sessions.

# 25. Inspecting Containers

You can inspect a container:

```bash
docker inspect my-nginx
```

This returns detailed information, including things such as:

- Container configuration
    
- Network settings
    
- Mounts
    
- Environment
    
- Image information
    
- State
    

The output is usually JSON.

---

# 26. Copying Files

Docker CLI can copy files between your host and a container.

Host → Container:

```bash
docker cp file.txt my-nginx:/tmp/file.txt
```

Container → Host:

```bash
docker cp my-nginx:/tmp/file.txt ./file.txt
```

This is useful for debugging and transferring files.

# 30. Docker System Commands

Docker provides system-level commands.

Check disk usage:

```bash

```

Clean unused Docker resources:

```bash

```

Be careful with cleanup commands.

Before using destructive commands, understand what resources will be removed.

# 35. Important Difference: `run` vs `start`

This is very important.

### `docker run`

Creates a **new container** from an image and starts it.

```text
Image
 ↓
New Container
 ↓
Running
```

### `docker start`

Starts an **existing stopped container**.

```text
Existing Container
       ↓
     Start
       ↓
    Running
```

Remember:

```text
docker run
    =
create + start

docker start
    =
start existing container
```

---

# 36. Important Difference: Image vs Container Commands

Images:

```bash
docker image ls
docker image pull nginx
docker image rm nginx
```

Containers:

```bash
docker container ls
docker container start NAME
docker container stop NAME
docker container rm NAME
```

Mental model:

```text
IMAGE
  ↓
docker run
  ↓
CONTAINER
```
