Git is used because managing a project without version control quickly becomes difficult.

Imagine saving multiple copies of the same project:

```text
project/
├── project-final/
├── project-final-v2/
├── project-final-v3/
├── project-final-fixed/
└── project-final-really-final/
```

This approach creates confusion:

- Which version is the latest?
    
- What changed between versions?
    
- Who changed a file?
    
- How can you restore an older version?
    
- How can multiple developers work safely?
    

**Git solves these problems.**

---

## 1. Git tracks changes

Git records changes made to your project over time.

```text
Version 1
    │
    ▼
Version 2
    │
    ▼
Version 3
    │
    ▼
Version 4
```

Instead of manually creating copies, Git stores the project's history as **commits**.

```text
A ─── B ─── C ─── D
```

Each commit represents a point in the history of the project.

You can inspect that history with:

```bash
git log
```

---

# 2. Git lets you go back in time

Suppose your application worked correctly yesterday:

```text
Commit A ─── Commit B ─── Commit C
                         ▲
                    Bug introduced
```

Git allows you to inspect earlier versions and, when appropriate, restore or recover work.

This makes experimentation much safer.

```text
Past ◄──────── Git History ────────► Present
```

---

# 3. Git helps you understand what changed

Git can compare different versions of your files.

For example:

```diff
- console.log("Hello");
+ console.log("Hello, Git!");
```

You can inspect changes using:

```bash
git diff
```

This helps answer:

- What did I change?
    
- Which files changed?
    
- What changed before the last commit?
    
- What changed between two commits?
    

---

# 4. Git provides a history of your project

A project can evolve over months or years.

Git keeps a structured history:

```text
A  Initial project
│
B  Add user authentication
│
C  Fix login validation
│
D  Add dashboard
│
E  Improve performance
```

Each commit can contain information such as:

- What changed
    
- Who created the commit
    
- When it was created
    
- Its parent commit(s)
    

---

# 5. Git makes branching easy

One of Git's most powerful features is **branching**.

Suppose your main application is stable:

```text
main

A ─── B ─── C
```

You want to develop a new feature without affecting the stable code.

Create a branch:

```text
main

A ─── B ─── C
       \
        D ─── E
             feature
```

Now you can work independently on the feature.

```bash
git switch -c feature
```

When the feature is ready, it can be merged back.

```text
A ─── B ─── C ─── F
       \         /
        D ─── E
```

---

# 6. Git makes experimentation safer

Without Git, you might be afraid to make major changes.

With a branch:

```text
main
 │
 ├── Stable code
 │
 └── experiment branch
        │
        ├── Try idea A
        ├── Try idea B
        └── Test changes
```

If the experiment fails, you can abandon the branch without changing the stable branch.

---

# 7. Git supports collaboration

Multiple developers can work on the same project.

```text
                    Remote Repository
                           │
             ┌─────────────┼─────────────┐
             ▼             ▼             ▼
       Developer A   Developer B   Developer C
```

Each developer can:

1. Clone the repository
    
2. Create a branch
    
3. Make changes
    
4. Create commits
    
5. Share their work
    
6. Merge approved changes
    

Git provides the underlying version-control mechanisms that make this workflow possible.

---

# 8. Git works offline

Git is a **distributed version control system**.

A local repository contains the information needed for many core operations.

You can:

```bash
git status
git add .
git commit -m "Add feature"
git log
git diff
git branch
```

without being connected to the internet.

You usually need network access only when communicating with a remote repository:

```text
Local Repository
       │
       │ Internet
       ▼
Remote Repository
```

For example:

```bash
git push
git fetch
git pull
```

---

# 9. Git is fast

Most everyday Git operations happen locally.

For example:

```bash
git status
git log
git diff
git commit
```

Because the core repository is on your computer, Git can perform many operations without contacting a server.

---

# 10. Git helps recover lost work

Sometimes developers:

- Delete a branch accidentally
    
- Move to the wrong commit
    
- Reset changes
    
- Lose track of recent commits
    

Git contains recovery tools that can often help.

For example:

```bash
git reflog
```

The reflog records updates to references such as `HEAD`, making it useful for finding commits that may no longer be easily visible from a branch.

```text
HEAD history

A ─── B ─── C
          ▲
     Lost branch?

git reflog
     │
     ▼
Find previous reference
```

|---|---|---|

|Experimenting|Risky|Branches|
