A **Version Control System (VCS)** is a tool that records and manages changes to files over time.

It allows you to answer questions such as:

- What changed?
    
- When did it change?
    
- Who changed it?
    
- Why was it changed?
    
- Can we return to an earlier version?
    

> **A VCS helps you manage the history of a project.**

---

# 1. The Problem Without Version Control

Imagine working on a project without a VCS.

You might create multiple copies:

```text
project/
├── project-original/
├── project-v2/
├── project-v3/
├── project-final/
├── project-final-fixed/
└── project-final-really-final/
```

This creates several problems:

- Which version is the newest?
    
- Which version contains the correct changes?
    
- What changed between two versions?
    
- Can you safely restore an older version?
    
- How can multiple people work on the same project?
    

A Version Control System solves these problems by maintaining a structured history.

---

# 2. How a VCS Works

A VCS records versions of a project over time.

```text
Version 1
    │
    ▼
Version 2
    │
    ▼
Version 3
    │
    ▼
Version 4
```

Instead of manually creating folders, changes are recorded as versions or snapshots.

With Git, these recorded points are called **commits**:

```text
A ─── B ─── C ─── D
```

Each point represents part of the project's history.

---

# 3. Basic VCS Concepts

Most version control systems involve similar concepts.

## Repository

A **repository** stores the files and their version history.

```text
Repository
│
├── Current files
│
└── Version history
    ├── Version 1
    ├── Version 2
    └── Version 3
```

---

## Revision or Version

A **revision** is a recorded state or change in the history of a project.

Different VCS tools may use different terminology.

For example, Git commonly uses:

```text
Commit
```

---

## History

The VCS maintains a history of changes.

```text
Initial version
       │
       ▼
Add feature
       │
       ▼
Fix bug
       │
       ▼
Improve performance
```

This history allows developers to understand how a project evolved.

---

# 4. What Does a VCS Track?

A VCS can track changes such as:

```text
File created
     │
     ▼
File modified
     │
     ▼
File renamed
     │
     ▼
File deleted
```

For text files, it can also help identify the differences between versions.

Example:

```diff
- const message = "Hello";
+ const message = "Hello, World!";
```

---

# 5. Main Benefits of a VCS

## 1. Track Changes

A VCS records how files change over time.

```text
Version 1 ─── Version 2 ─── Version 3
```

You can inspect previous changes instead of guessing what happened.

---

## 2. Restore Previous Versions

Suppose a bug is introduced:

```text
A ─── B ─── C
            ▲
           Bug
```

A VCS allows you to inspect earlier versions and use the appropriate tools to restore or recover previous work.

---

## 3. Compare Versions

You can compare different versions of a file.

```text
Version A

Hello

Version B

Hello, World!
```

A VCS can show the difference:

```diff
- Hello
+ Hello, World!
```

---

## 4. Collaboration

Multiple people can work on the same project.

```text
                Repository
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    Developer A Developer B Developer C
```

The VCS helps organize and integrate their changes.

---

## 5. Branching

Many modern VCS tools support branching.

A branch allows development to continue independently.

```text
main

A ─── B ─── C
       \
        D ─── E
          feature
```

This is useful when developing features, fixing bugs, or experimenting.

# 6. Types of Version Control Systems

Version control systems have evolved over time.

There are three major categories:

```text
Version Control Systems
│
├── 1. Local VCS
│
├── 2. Centralized VCS
│
└── 3. Distributed VCS
```

---

# 7. Local Version Control Systems

A **Local Version Control System** stores version history on one computer.

```text
Your Computer
│
├── Project
│
└── Version Database
    ├── Version 1
    ├── Version 2
    └── Version 3
```

The history is stored locally.

### Advantages

- Simple
    
- No network required
    

### Disadvantages

- Difficult collaboration
    
- History may be lost if the computer fails
    
- No shared central repository by default
    

Local VCS tools are less common in modern team development.

---

# 8. Centralized Version Control Systems (CVCS)

A **Centralized Version Control System** uses a central server.

```text
                 Central Server
                 Repository
                      │
          ┌───────────┼───────────┐
          │           │           │
          ▼           ▼           ▼
       User A      User B      User C
```

The main repository exists on a central server.

Developers usually connect to that server to get and share changes.

### Examples

- Subversion (SVN)
    
- CVS
    
- Perforce
    

### Advantages

- Centralized management
    
- Simple access control
    
- Clear central source of shared history
    

### Disadvantages

- Greater dependence on the central server
    
- Network connectivity can be important for many operations
    
- Server failures can disrupt collaboration
    

---

# 9. Distributed Version Control Systems (DVCS)

A **Distributed Version Control System** gives each developer a local copy of the repository and its history.

```text
                  Remote Repository
                         │
              ┌──────────┼──────────┐
              │          │          │
              ▼          ▼          ▼
          Developer A Developer B Developer C
              │          │          │
              ▼          ▼          ▼
          Local Repo  Local Repo  Local Repo
```

Each developer can perform many version-control operations locally.

### Examples

- Git
    
- Mercurial
    

### Advantages

- Local history
    
- Many operations work offline
    
- Fast local operations
    
- Flexible collaboration workflows
    
- No single server is required for basic local version-control work
    

### Disadvantages

- Concepts can initially be more complex
    
- Multiple repositories and remotes may confuse beginners
    

---

# 10. Centralized vs Distributed VCS

|Feature|Centralized VCS|Distributed VCS|
|---|---|---|
|Repository history|Mainly centralized|Available in local clones|
|Offline work|More limited|Many operations work offline|
|Server dependence|Higher|Lower for local operations|
|Local commits|Often tied to central workflow|Fully supported|
|Collaboration|Central server model|Flexible remote model|
|Examples|SVN, CVS|Git, Mercurial|

# 11. Git as a Version Control System

Git is a **Distributed Version Control System (DVCS)**.

A simplified Git workflow is:

```text
Working Files
     │
     │ git add
     ▼
Staging Area
     │
     │ git commit
     ▼
Local Repository
     │
     │ git push
     ▼
Remote Repository
```

Git tracks project history through **commits**.

```text
A ─── B ─── C ─── D
```

It also supports branching:

```text
A ─── B ─── C
       \
        D ─── E
```

---

# 12. VCS and Remote Hosting Platforms

A VCS and a hosting platform are not necessarily the same thing.

For example:

```text
Git
│
└── Version Control System
```

While platforms such as GitHub and GitLab provide services around Git repositories:

```text
Hosting Platform
│
├── Repository hosting
├── Code review
├── Collaboration
├── Issues
├── CI/CD
└── Project management
```

The relationship looks like:

```text
             Version Control
                   │
                   ▼
                  Git
                   │
          ┌────────┴────────┐
          ▼                 ▼
        GitHub            GitLab
```

# 13. Common VCS Terminology

|Term|Meaning|
|---|---|
|**Version Control**|Managing changes to files over time|
|**Repository**|A collection of files and their history|
|**Commit**|A recorded change or snapshot in Git|
|**Revision**|A version in a project's history|
|**Branch**|An independent line of development|
|**Merge**|Combining changes from different lines of development|
|**Clone**|Creating a local copy of a repository|
|**Remote**|Another repository used for synchronization|
|**Diff**|The difference between versions|

# Summary

A **Version Control System (VCS)** is software that manages the history of files and projects.

It helps you:

1. **Track changes**
    
2. **Maintain version history**
    
3. **Compare versions**
    
4. **Restore earlier work**
    
5. **Collaborate with others**
    
6. **Create branches**
    
7. **Merge changes**
    
8. **Recover from mistakes**

VCS
