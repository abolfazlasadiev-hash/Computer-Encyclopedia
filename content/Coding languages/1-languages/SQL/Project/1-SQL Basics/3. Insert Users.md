# 🧠 Understanding `INSERT INTO`

The basic syntax is:

```sql
INSERT INTO table_name (
    column1,
    column2,
    column3
)
VALUES (
    value1,
    value2,
    value3
);
```

For your table:

```sql
INSERT INTO users (
    id,
    name,
    email,
    age,
    country
)
VALUES (
    1,
    'Abolfazl Asadi',
    'abolfazl@example.com',
    25,
    'Iran'
);
```

Think of it as:

```text
INSERT INTO
     ↓
Which table?

users
     ↓
Which columns?

id, name, email, age, country
     ↓
What values?

1, Abolfazl Asadi, ..., 25, Iran
```

# 🔍 Understanding Text and Numbers

There is an important difference between text and numbers.

### Numbers

Numbers do **not** need quotes:

```sql
25
31
100
```

For example:

```sql
age = 25
```

---

### Text

Text values are written inside quotes:

```sql
'Abolfazl Asadi'
'Iran'
'abolfazl@example.com'
```

For example:

```sql
name = 'Abolfazl Asadi'
```

So:

```sql
(1, 'Abolfazl Asadi', 'abolfazl@example.com', 25, 'Iran')
```

means:

```text
1                       → number
'Abolfazl Asadi'        → text
'abolfazl@example.com'  → text
25                      → number
'Iran'                  → text
```

---

# 🧩 Understanding Columns and Values

These columns:

```sql
INSERT INTO users (
    id,
    name,
    email,
    age,
    country
)
```

must correspond to these values:

```sql
VALUES (
    1,
    'Abolfazl Asadi',
    'abolfazl@example.com',
    25,
    'Iran'
);
```

The order matters.

```text
id       → 1
name     → Abolfazl Asadi
email    → abolfazl@example.com
age      → 25
country  → Iran
```

Think of it as matching two lists:

```text
Columns              Values
──────────────────────────────
id          →        1
name        →        Abolfazl Asadi
email       →        abolfazl@example.com
age         →        25
country     →        Iran
```

# ⚠️ Important: Don't Accidentally Insert Twice

If you run the same `INSERT` statement twice, you will insert the same five users again.

Your table could become:

```text
1 Abolfazl
2 Sara
3 Daniel
4 Emma
5 Alex

1 Abolfazl
2 Sara
3 Daniel
4 Emma
5 Alex
```

Because Project #2 did not yet add a primary key constraint, MySQL may allow those duplicate IDs.

For this project, that's a useful lesson:

> Constraints are what help databases protect data integrity.

You will learn constraints later in your roadmap.

For now, **run the insert script only once** on your practice database, or clear/recreate the table if you're intentionally starting over.

# 🧱 SQL Concepts Practiced

## INSERT INTO

The `INSERT INTO` statement is used to add records to a table.

Example:

```sql
INSERT INTO users (
    id,
    name,
    email,
    age,
    country
)
VALUES (
    1,
    'Abolfazl Asadi',
    'abolfazl@example.com',
    25,
    'Iran'
);
```

---

## Single-Row Insert

A single record can be inserted using one `VALUES` row:

```sql
INSERT INTO users (
    id,
    name,
    email,
    age,
    country
)
VALUES (
    1,
    'Abolfazl Asadi',
    'abolfazl@example.com',
    25,
    'Iran'
);
```

This adds one row to the table.

---

## Multi-Row Insert

Multiple records can be inserted using one SQL statement:

```sql
INSERT INTO users (
    id,
    name,
    email,
    age,
    country
)
VALUES
    (1, 'Abolfazl Asadi', 'abolfazl@example.com', 25, 'Iran'),
    (2, 'Sara Johnson', 'sara@example.com', 24, 'Canada'),
    (3, 'Daniel Smith', 'daniel@example.com', 29, 'Germany');
```

This is more convenient than writing a separate `INSERT` statement for every user.

---

## Text Values

Text values are written inside single quotes:

```sql
'Iran'
'Sara Johnson'
'sara@example.com'
```

For example:

```sql
name = 'Sara Johnson'
```

---

## Numeric Values

Numeric values do not need quotes:

```sql
1
24
29
31
```

For example:

```sql
age = 24
```

# ⚠️ Important Note About Duplicate Data

Running the same `INSERT` statement multiple times will insert the records again.

For example, running the script twice may result in:

```text

2 | Sara Johnson
3 | Daniel Smith
...
1 | Abolfazl Asadi
2 | Sara Johnson
3 | Daniel Smith
...
```

This happens because the current table does not yet have a primary key or other constraints preventing duplicate IDs.

Database constraints will be studied later in the roadmap.
