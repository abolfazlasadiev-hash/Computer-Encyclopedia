## 1. Definition

**Docker is a platform for building, packaging, and running applications inside containers.**

A container packages an application together with the things it needs to run, such as:

- Application code
    
- Libraries
    
- Dependencies
    
- Configuration
    
- Runtime environment
    

The goal is to make applications run consistently across different environments.

---

# 2. The Problem Docker Solves

Before containers, developers often experienced problems like:

> "It works on my computer, but it doesn't work on the server."

For example:

```text
Developer Computer
------------------
Python 3.12
Library A version 2
Library B version 5
Ubuntu
        ↓
        Works
```

But the server might have:

```text
Production Server
-----------------
Python 3.10
Library A version 1
Library B version 4
Different Linux configuration
        ↓
        Doesn't work
```

Docker helps package the application environment so the application can run more consistently.

# 3. Docker in Simple Terms

Think of Docker as a **box for your application**.

```text
┌─────────────────────────────┐
│       Docker Container      │
│                             │
│  Application                │
│  Libraries                  │
│  Dependencies               │
│  Configuration              │
│                             │
└─────────────────────────────┘
```

You can move that container between environments:

```text
Your Computer
      ↓
Docker Container
      ↓
Testing Server
      ↓
Production Server
```

---

# 4. What Is a Container?

A **container** is an isolated environment used to run an application.

Example:

```text
Container
│
├── Application
├── Dependencies
├── Environment
└── Processes
```

Containers share the host operating system's kernel, which makes them generally lighter and faster to start than traditional virtual machines.

---

# 5. What Is an Image?

A Docker **image** is a packaged template used to create containers.

Think of it like this:

```text
Docker Image
     │
     │ docker run
     ↓
Docker Container
```

For example:

```bash
docker pull nginx
```

downloads the Nginx image.

Then:

```bash
docker run nginx
```

creates and starts a container from that image.

---

# 6. Image vs Container

This is one of the most important Docker concepts.

|Image|Container|
|---|---|
|Template|Running instance|
|Read-only layers|Writable container layer|
|Used to create containers|Runs the application|
|Can be stored and shared|Has a lifecycle|
|Example: `nginx:latest`|Example: `my-nginx`|

A simple analogy:

```text
Image     = Class / Blueprint
Container = Object / Running Instance
```

Another analogy:

```text
Image     = Recipe
Container = Prepared Meal
```

```text
┌──────────────────────────────┐
│          Your Computer       │

│   ┌──────────────────────┐   │
```

```bash

```

```bash

```

The Docker CLI communicates with the Docker Engine.

# 9. Docker vs Virtual Machines

Docker containers are different from virtual machines.

### Virtual Machine

```text
Computer
│
├── Host OS
│
├── Hypervisor
│   │
│   ├── VM 1
│   │   ├── Guest OS
│   │   └── Application
│   │
│   └── VM 2
│       ├── Guest OS
│       └── Application
```

Each VM includes a complete guest operating system.

### Containers

```text
Computer
│
├── Host OS
│
├── Docker Engine
│
├── Container 1
│   └── Application
│
├── Container 2
│   └── Application
│
└── Container 3
    └── Application
```

Containers share the host kernel rather than each carrying a complete guest OS.

# 10. Why Developers Use Docker

Docker is commonly used for:

- Development
    
- Testing
    
- CI/CD
    
- Application deployment
    
- Microservices
    
- Databases
    
- Web servers
    
- Backend applications
    
- Development environments
    

For example, instead of installing MySQL directly on your computer, you can run MySQL in a Docker container.

```text
Computer
   │
   └── Docker
        │
        └── MySQL Container
```

# 11. Example

Let's run Nginx.

First download the image:

```bash
docker pull nginx
```

Run it:

```bash
docker run --name my-nginx nginx
```

Check running containers:

```bash
docker ps
```

You might see:

```text
CONTAINER ID   IMAGE   COMMAND   STATUS   NAMES
xxxxxxxxxxxx   nginx   ...       Up       my-nginx
```

Stop it:

```bash
docker stop my-nginx
```

Remove it:

```bash
docker rm my-nginx
```

The image can still exist after the container is removed.

Check images:

```bash
docker images
```

# 12. Important Docker Terms

Learn these terms early:

### Docker

The platform and ecosystem for working with containers.

### Docker Engine

The software that creates and manages Docker containers, images, networks, and volumes.

### Docker CLI

The command-line interface used to interact with Docker.

Example:

```bash
docker ps
```

### Image

A packaged template from which containers are created.

Example:

```text
nginx:latest
```

### Container

A running or stopped instance created from an image.

Example:

```text
my-nginx
```

### Dockerfile

A text file containing instructions for building a Docker image.

Example:

```dockerfile
FROM nginx
```

### Docker Hub

A public registry where Docker images can be stored and shared.

# 16. Key Takeaways

Remember these five ideas:

```text
1. Docker runs applications in containers.

2. Images are templates used to create containers.

3. Containers are running instances of images.

4. Dockerfiles describe how images are built.

5. Docker CLI is used to control Docker.
```

The most important relationship is:

```text
Dockerfile
    ↓
Image
    ↓
Container
```
