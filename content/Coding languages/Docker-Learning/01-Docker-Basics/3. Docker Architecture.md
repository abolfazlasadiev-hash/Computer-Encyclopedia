# 🐳 Docker Architecture

## 1. Overview

Docker uses a **client-server architecture**.

The main components are:

```text
Docker Client
      ↓
Docker Host
      ↓
Docker Daemon
      ↓
Containers / Images / Networks / Volumes
```

Understanding this architecture makes Docker commands much easier to understand.

---

# 2. The Main Docker Components

Docker architecture has three important parts:

```text
┌──────────────────────┐
│    Docker Client     │
│       (CLI)          │
└──────────┬───────────┘
           │
           │ Docker API
           ↓
┌──────────────────────┐
│    Docker Daemon     │
│      dockerd         │
└──────────┬───────────┘
           │
           ├── Images
           ├── Containers
           ├── Networks
           └── Volumes
```

The three concepts to remember first are:

1. **Docker Client**
    
2. **Docker Daemon**
    
3. **Docker Host**
    

---

# 3. Docker Client

The **Docker Client** is the tool you use to communicate with Docker.

Most commonly, this is the `docker` command.

For example:

```bash
docker ps
```

or:

```bash
docker images
```

or:

```bash
docker run nginx
```

The Docker CLI sends requests to the Docker daemon.

---

# 4. Docker Daemon

The **Docker daemon** is a background service responsible for managing Docker resources.

The daemon process is called:

```text
dockerd
```

It manages things such as:

- Containers
    
- Images
    
- Networks
    
- Volumes
    

Conceptually:

```text
Docker CLI
    │
    │ Request
    ↓
dockerd
    │
    ├── Containers
    ├── Images
    ├── Networks
    └── Volumes
```

---

# 5. Docker Host

The **Docker host** is the system where Docker Engine is running.

On your Debian machine, conceptually:

```text
Debian Linux
│
└── Docker Engine
    │
    ├── Docker Daemon
    ├── Containers
    ├── Images
    ├── Networks
    └── Volumes
```

Your Debian computer is acting as the Docker host.

---

# 6. Docker Engine

**Docker Engine** is the core technology used to build and run containers.

A simplified view:

```text
Docker Engine
│
├── Docker CLI
│
├── Docker Daemon
│
├── Container runtime
│
└── Docker APIs
```

Docker Engine provides the functionality needed to:

- Build images
    
- Run containers
    
- Stop containers
    
- Remove containers
    
- Manage networks
    
- Manage volumes
    

---

# 7. Docker Client → Docker Daemon

When you execute:

```bash
docker ps
```

the command does not itself directly inspect containers.

Instead:

```text
You
 │
 │ docker ps
 ↓
Docker CLI
 │
 │ API request
 ↓
Docker Daemon
 │
 │
 ↓
Container information
```

The daemon processes the request and returns the result to the client.

---

# 8. Docker API

The Docker Client communicates with the daemon through the **Docker API**.

Simplified:

```text
Docker CLI
     │
     │ Docker API
     ↓
Docker Daemon
```

The API allows programs to communicate with Docker programmatically.

This means Docker doesn't have to be controlled only through the command line.

Other applications can communicate with Docker through its API.

---

# 9. Docker Objects

Docker manages several important objects.

The most important are:

```text
Docker
│
├── Images
├── Containers
├── Networks
└── Volumes
```

Let's understand each one.

---

# 10. Images

An **image** is a template used to create containers.

Example:

```bash
docker pull nginx
```

You can see your images with:

```bash
docker images
```

Architecture:

```text
Docker Daemon
     │
     └── Images
          ├── nginx
          ├── mysql
          └── python
```

---

# 11. Containers

A **container** is created from an image.

For example:

```bash
docker run nginx
```

Conceptually:

```text
nginx Image
     │
     │ docker run
     ↓
nginx Container
```

The daemon manages the container.

```text
Docker Daemon
     │
     └── Containers
          ├── nginx
          ├── mysql
          └── python
```

---

# 12. Networks

Docker networks allow containers to communicate with each other.

Example:

```text
┌───────────────┐
│ Web Container │
└───────┬───────┘
        │
     Network
        │
┌───────▼────────┐
│ API Container  │
└───────┬────────┘
        │
     Network
        │
┌───────▼─────────┐
│ Database        │
│ Container       │
└─────────────────┘
```

Docker manages these networks through the daemon.

---

# 13. Volumes

Volumes provide persistent storage for containers.

Normally, container filesystems are temporary.

A volume allows data to survive when a container is removed.

```text
Container
    │
    │
    ↓
 Volume
    │
    ↓
Persistent Data
```

Example:

```bash
docker volume create my-data
```

List volumes:

```bash
docker volume ls
```

# 15. Example: `docker run`

Let's understand what happens when you run:

```bash
docker run nginx
```

### Step 1 — You enter the command

```bash
docker run nginx
```

### Step 2 — Docker CLI receives the command

```text
Docker CLI
```

### Step 3 — CLI communicates with the daemon

```text
Docker CLI
    │
    ↓
Docker API
    │
    ↓
Docker Daemon
```

### Step 4 — Daemon checks for the image

```text
Does nginx image exist locally?
```

If it doesn't exist, Docker may pull it from a registry.

```text
Docker Daemon
      │
      ↓
Docker Registry
      │
      ↓
nginx Image
```

### Step 5 — Container is created

```text
nginx Image
     ↓
nginx Container
```

### Step 6 — Container starts

```text
nginx Container
     │
     └── nginx process
```

# 16. Example Workflow

The complete workflow:

```text
You
 │
 │ docker run nginx
 ↓
Docker CLI
 │
 │ Docker API
 ↓
Docker Daemon
 │
 ├── Check Image
 │
 ├── Pull Image if necessary
 │
 ├── Create Container
 │
 ├── Configure Network
 │
 ├── Configure Storage
 │
 └── Start Container
        │
        ↓
     Nginx
```

# 17. Docker Registry

A **Docker registry** stores Docker images.

A common public registry is Docker Hub.

The relationship looks like:

```text
Docker Registry
      │
      │ Pull
      ↓
Docker Daemon
      │
      ↓
Docker Image
      │
      ↓
Docker Container
```

For example:

```bash
docker pull nginx
```

Docker downloads the image from a registry.

---

# 18. Local vs Remote Docker

The Docker CLI and Docker daemon don't necessarily have to run on the same machine.

### Local

```text
Your Computer
│
├── Docker CLI
│
└── Docker Daemon
```

This is the typical beginner setup.

### Remote

```text
Your Computer
│
└── Docker CLI
       │
       │ API
       ↓
Remote Server
│
└── Docker Daemon
```

This allows you to control Docker running on another machine.

# 19. Check Your Docker Architecture

On your Debian machine, run:

```bash
docker version
```

You will typically see both:

```text
Client:
...

Server:
...
```

This is useful because Docker uses a client-server architecture.

---

## Check Docker Information

Run:

```bash
docker info
```

This provides information about the Docker daemon and Docker environment.

---

## Check Docker Processes

On Debian, you can also check the Docker service:

```bash
systemctl status docker
```

You may see something similar to:

```text
Active: active (running)
```

If Docker is running, the daemon is active.

# 22. Key Terms

|Term|Meaning|
|---|---|
|Docker Client|Tool used to communicate with Docker|
|Docker CLI|Command-line Docker client|
|Docker Daemon|Background service managing Docker|
|`dockerd`|Docker daemon process|
|Docker Engine|Core Docker container technology|
|Docker API|Interface used to communicate with the daemon|
|Image|Template for creating containers|
|Container|Running/stopped instance of an image|
|Network|Allows containers to communicate|
|Volume|Persistent container storage|
|Registry|Stores and distributes images|
|Docker Host|Machine running Docker|
