## 1. Overview

A **Docker container** is a running or stopped instance created from a Docker image.

Remember the relationship:

```text
Docker Image
     ↓
 docker run
     ↓
Docker Container
     ↓
Running Application
```

A simple mental model is:

```text
Image      = Template
Container  = Instance
```

For example:

```bash
docker run nginx
```

Docker uses the `nginx` image to create a container.

---

# 2. What Is a Container?

A container is an isolated environment in which a process or application can run.

A container can have its own:

- Filesystem view
    
- Processes
    
- Network environment
    
- Environment variables
    
- Hostname
    
- Resource limits
    
- Configuration
    

But containers share the host operating system's kernel.

Simplified:

```text
Host Linux System
│
├── Docker Engine
│
├── Container 1
│   └── Application
│
├── Container 2
│   └── Application
│
└── Container 3
    └── Application
```

---

# 3. Container vs Image

This distinction is extremely important.

|Docker Image|Docker Container|
|---|---|
|Template|Instance|
|Read-only image layers|Image layers + writable container layer|
|Used to create containers|Created from an image|
|Can be stored in a registry|Runs on Docker Engine|
|Can create many containers|Represents one container instance|

Example:

```text
             nginx IMAGE
                 │
        ┌────────┼────────┐
        ↓        ↓        ↓
     web-1     web-2     web-3
   container  container  container
```

One image can create many containers.

---

# 4. Creating a Container

The most common way to create and start a container is:

```bash
docker run nginx
```

The general syntax is:

```bash
docker run IMAGE
```

For example:

```bash
docker run nginx
```

Docker will:

```text
Find image
    ↓
Create container
    ↓
Configure container
    ↓
Start container
    ↓
Run its main process
```

---

# 5. `docker run`

`docker run` is one of the most important Docker commands.

Example:

```bash
docker run nginx
```

Conceptually:

```text
docker run
    │
    ├── Find image
    ├── Create container
    ├── Configure container
    └── Start container
```

If the image isn't available locally, Docker can pull it from a registry when appropriate.

---

# 6. Running in Detached Mode

By default, some containers attach their main process to your terminal.

To run a container in the background:

```bash
docker run -d nginx
```

The `-d` option means:

```text
detached
```

Example:

```bash
docker run -d --name my-nginx nginx
```

Your terminal remains available.

Check the container:

```bash
docker ps
```

---

# 7. Naming Containers

Docker can generate a name automatically.

You can instead provide your own name:

```bash
docker run -d --name my-nginx nginx
```

Here:

```text
--name
    ↓
my-nginx
```

The name makes it easier to manage the container.

For example:

```bash
docker stop my-nginx
```

is easier to remember than a generated name.

# 11. Running State

A running container has its main process running.

Check:

```bash
docker ps
```

You may see:

```text
STATUS
Up 2 minutes
```

This means the container is currently running.

---

# 12. Stopped State

Stop a container:

```bash
docker stop my-nginx
```

Then:

```bash
docker ps
```

It will no longer appear because `docker ps` shows running containers.

Use:

```bash
docker ps -a
```

and you may see:

```text
STATUS
Exited (...)
```

The container still exists.

It is simply stopped.

---

# 13. Starting a Stopped Container

If a container already exists but is stopped:

```bash
docker start my-nginx
```

Then:

```bash
docker ps
```

The container should be running again.

Remember:

```text
docker run
    ↓
Create + Start NEW container

docker start
    ↓
Start EXISTING container
```

---

# 14. Stopping a Container

Use:

```bash
docker stop my-nginx
```

Docker asks the container's main process to terminate gracefully.

If the process does not stop within Docker's configured grace period, Docker can forcefully terminate it.

For normal administration, prefer:

```bash
docker stop
```

over immediately using:

```bash
docker kill
```

---

# 15. Restarting a Container

Restart a container:

```bash
docker restart my-nginx
```

Conceptually:

```text
Running
   ↓
Stop
   ↓
Start
   ↓
Running
```

This is useful when an application needs to be restarted.

---

# 16. Removing a Container

Remove a stopped container:

```bash
docker rm my-nginx
```

After removal:

```bash
docker ps -a
```

The container should no longer appear.

Important:

```text
docker stop
    ↓
Stops container

docker rm
    ↓
Removes container
```

Stopping and removing are different operations.

---

# 17. Force Removing a Container

You can force removal:

```bash
docker rm -f my-nginx
```

This can stop and remove a running container.

Use this carefully.

Prefer understanding the container's state before using force.

# 19. Container IDs

Docker assigns each container an ID.

Run:

```bash
docker ps
```

You may see:

```text

```

Docker often displays a shortened ID in listings.


You generally don't need to type the entire ID if the shortened value uniquely identifies the container.

# 20. Container Hostname

A container has a hostname.

You can check it from inside the container:

```bash
docker exec my-nginx hostname
```

You can also specify a hostname when creating a container:

```bash
docker run -d --hostname web-server --name my-nginx nginx
```

Now the container has a configured hostname:

```text
web-server
```

Hostname and container name are related concepts, but they are not the same thing.

```text
Container name
    ↓
my-nginx

Hostname
    ↓
web-server
```

# 21. Container Ports

A container can listen on a port.

For example, Nginx commonly listens on:

```text
80
```

Inside the container:

```text
Nginx
  ↓
Port 80
```

To publish it on the host:

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

The format is:

```text
-p HOST_PORT:CONTAINER_PORT
```

So:

```text
8080:80
```

means:

```text
Host
Port 8080
    ↓
Container
Port 80
```

---

# 22. Why Port Publishing Is Needed

Containers have their own network environment.

A service listening inside a container is not automatically published on every host port.

For example:

```bash
docker run -d nginx
```

starts Nginx, but you have not explicitly published its HTTP port to a host port.

To publish it:

```bash
docker run -d -p 8080:80 nginx
```

Now the host can accept connections on port `8080` and forward them to port `80` in the container.

# 23. Container Environment Variables

Containers can receive environment variables.

Example:

```bash
docker run -d \
  --name my-app \
  -e APP_ENV=development \
  nginx
```

Here:

```text
APP_ENV=development
```

is passed into the container environment.

You can inspect environment configuration with:

```bash
docker inspect my-app
```

Environment variables are commonly used to configure applications without changing the image itself.

---

# 24. Container Filesystem

A container has its own filesystem view.

For example:

```bash
docker exec -it my-nginx sh
```

Then:

```bash
ls
```

You are looking at the container's filesystem.

The container filesystem is based on the image plus a writable container layer.

Simplified:

```text
Container Filesystem
│
├── Writable container layer
│
├── Image layer
├── Image layer
└── Image layer
```

---

# 25. Container Writable Layer

When a container modifies a file, the modification normally goes into its writable container layer.

For example:

```text
Image
  ↓
Read-only layers
  ↓
Writable container layer
  ↓
Container
```

This writable layer is useful for temporary runtime changes.

However, it is not a good replacement for persistent storage.

For persistent data, Docker volumes or bind mounts are commonly used.

---

# 26. Container Processes

A container runs processes.

A useful mental model is:

```text
Container
    ↓
Main Process
    ↓
Application
```

For example:

```text
Nginx Container
      ↓
nginx process
```

The lifecycle of the main process is important.

If the main process exits, the container normally stops.

---

# 27. The Main Container Process

Suppose you run:

```bash
docker run nginx
```

The container's main process is the process Docker is tracking as the container's primary process.

If that process terminates, the container normally exits.

Simplified:

```text
Container starts
      ↓
Main process starts
      ↓
Application runs
      ↓
Main process exits
      ↓
Container exits
```

This is a very important Docker concept.

```text
    ↓
```

# 37. Containers Are Not Virtual Machines

A container is not a complete virtual machine.

Simplified:

```text
Virtual Machines
────────────────────────
Host
 ↓
Hypervisor
 ↓
Guest OS
 ↓
Application
```

Containers:

```text
Containers
────────────────────────
Host Linux
 ↓
Docker Engine
 ↓
Containers
 ↓
Applications
```

Containers share the host kernel.

This is one reason containers can be lightweight compared with traditional virtual machines.

# 40. `docker run` vs `docker create`

### `docker run`

```bash
docker run nginx
```

Conceptually:

```text
Create
  +
Start
```

### `docker create`

```bash
docker create nginx
```

Conceptually:

```text
Create only
```

Then:

```bash
docker start CONTAINER
```

starts it.

So:

```text
docker run
    ≈
docker create + docker start
```

This is a useful mental model.

---

# 41. `docker kill`

Docker also provides:

```bash
docker kill my-nginx
```

This immediately sends a kill signal to the container's main process by default.

Compare:

```text
docker stop
    ↓
Graceful shutdown attempt

docker kill
    ↓
Immediate termination
```

Use `docker stop` for normal shutdowns whenever possible.

# 42. Copying Files

You can copy files between your host and a container.

Host → Container:

```bash
docker cp ./config.txt my-nginx:/tmp/config.txt
```

Container → Host:

```bash
docker cp my-nginx:/tmp/config.txt ./config.txt
```

This can be useful for debugging and temporary file transfer.

For application data that must persist, use an appropriate volume or bind mount instead.

Containers have a writable layer, but important data should generally not depend on that layer.

For persistent data, Docker provides storage mechanisms such as:


```bash

  --name mysql-db \
  -v mysql-data:/var/lib/mysql \
```

Here:

```text

    ↓
Persistent Docker volume
    ↓
Container
```

# 51. Common Beginner Mistakes

## Mistake 1 — Thinking a Container Is an Image

Wrong:

```text
Container = Image
```

Correct:

```text
Image
  ↓
Container
```

---

## Mistake 2 — Using `start` for a New Container

This will not create a new container:

```bash
docker start nginx
```

`docker start` expects an existing container.

To create a new container:

```bash
docker run nginx
```

---

## Mistake 3 — Thinking Stop Removes a Container

This:

```bash
docker stop my-container
```

only stops it.

It still exists.

Check:

```bash
docker ps -a
```

To remove it:

```bash
docker rm my-container
```

---

## Mistake 4 — Using `docker ps` and Expecting Stopped Containers

This:

```bash
docker ps
```

shows running containers.

Use:

```bash
docker ps -a
```

for all containers.

---

## Mistake 5 — Forgetting Port Publishing

Running:

```bash
docker run -d nginx
```

does not mean the Nginx HTTP service is automatically available on your desired host port.

Use:

```bash
docker run -d -p 8080:80 nginx
```

when you need to publish that port.

---

## Mistake 6 — Storing Important Data Only in the Container

Data stored only in the container's writable layer is not the same as persistent storage.

For important application data, learn:

```text
Volumes
Bind mounts
Backups
```

# 56. Key Takeaways

A Docker container is an isolated runtime environment created from an image.

The most important commands are:

```bash
docker run
docker ps
docker ps -a
docker create
docker start
docker stop
docker restart
docker rm
docker logs
docker exec
docker inspect
docker top
docker stats
docker cp
```

Remember these differences:

```text
docker run
    ↓
Create + start a new container


docker create
    ↓
Create container without starting it


docker start
    ↓
Start existing container


docker stop
    ↓
Stop running container


docker rm
    ↓
Remove container
```

The most important mental model:

```text
Docker Image
     ↓
Container
     ↓
Process
     ↓
Application
```
