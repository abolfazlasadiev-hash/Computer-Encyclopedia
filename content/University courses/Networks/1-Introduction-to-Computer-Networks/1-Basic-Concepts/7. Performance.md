
In **computer networks**, **performance** refers to how efficiently a network transfers data from one device to another.

A high-performance network should transfer data **quickly, efficiently, and consistently**.

The main factors used to describe network performance are:

1. **Bandwidth**
    
2. **Throughput**
    
3. **Goodput**
    
4. **Latency**
    
5. **Delay**
    
6. **Jitter**
    
7. **Packet Loss**
    

---

## 1. Bandwidth

**Bandwidth** is the maximum amount of data that a network link can theoretically carry per unit of time.

It is usually measured in:

- bits per second (**bps**)
    
- Kbps
    
- Mbps
    
- Gbps
    

### Example

A network connection has a bandwidth of:

**100 Mbps**

This means the link can theoretically carry up to **100 million bits per second**.

> **Bandwidth = capacity of the network link**

Think of bandwidth as the **width of a highway**. A wider highway can carry more vehicles at the same time.

---

## 2. Throughput

**Throughput** is the **actual amount of data successfully delivered** through the network per unit of time.

For example:

- Theoretical bandwidth = **100 Mbps**
    
- Actual throughput = **80 Mbps**
    

The network is capable of 100 Mbps, but only 80 Mbps is actually being achieved.

### Why is throughput lower?

Because of things such as:

- Network congestion
    
- Protocol overhead
    
- Interference
    
- Processing delays
    
- Packet loss
    
- Hardware limitations
    

> **Bandwidth = theoretical capacity**  
> **Throughput = actual data transfer rate**

---

## 3. Goodput

**Goodput** is the rate at which **useful application data** is successfully delivered, excluding protocol overhead, retransmitted data, and other unnecessary traffic.

For example:

Suppose:

- Throughput = 80 Mbps
    
- Some of that consists of headers and retransmissions
    
- Actual useful application data = 70 Mbps
    

Then:

**Goodput = 70 Mbps**

### Difference

**Bandwidth → maximum capacity**

**Throughput → actual network data**

**Goodput → useful application data**

---

## 4. Latency

**Latency** is the amount of time it takes for data to travel from the source to the destination.

It is normally measured in **milliseconds (ms)**.

For example:

A packet takes **40 ms** to reach the destination.

Therefore:

**Latency = 40 ms**

Lower latency generally means a more responsive network.

### Applications sensitive to latency

- Online gaming
    
- Video conferencing
    
- Voice calls
    
- Remote desktop
    
- Financial transactions
    

---

## 5. Delay

**Delay** is the time required for a packet to move through the network.

There are several types of delay.

### A. Processing Delay

Time required by a device such as a router to:

- Examine a packet
    
- Check its header
    
- Determine what to do with it
    

### B. Queuing Delay

Time a packet spends **waiting in a queue** before transmission.

This usually increases when the network becomes congested.

### C. Transmission Delay

Time required to place all the packet's bits onto the transmission link.

It depends on:

- Packet size
    
- Transmission rate
    

Formula:

Ttransmission=Packet SizeTransmission RateT_{transmission} = \frac{\text{Packet Size}}{\text{Transmission Rate}}

### D. Propagation Delay

Time required for the signal to physically travel through the medium.

It depends mainly on:

- Distance
    
- Signal propagation speed
    

### Total Delay

A simplified model is:

Dtotal=Dprocessing+Dqueuing+Dtransmission+DpropagationD_{total}=D_{processing}+D_{queuing}+D_{transmission}+D_{propagation}

---

## 6. Jitter

**Jitter** is the **variation in packet delay**.

Imagine packets being sent every 20 ms.

Ideally:

```text
Packet 1 → 20 ms
Packet 2 → 20 ms
Packet 3 → 20 ms
Packet 4 → 20 ms
```

Very little jitter.

But suppose:

```text
Packet 1 → 20 ms
Packet 2 → 35 ms
Packet 3 → 18 ms
Packet 4 → 50 ms
```

The delays are changing significantly.

That is **high jitter**.

### Why is jitter a problem?

It can cause:

- Choppy voice
    
- Video freezing
    
- Audio/video synchronization problems
    
- Poor online gaming experience
    

> **Latency = how long a packet takes**  
> **Jitter = how much that time varies**

---

## 7. Packet Loss

**Packet loss** occurs when packets sent through a network **fail to reach their destination**.

Example:

```text
Sender
  │
  ├── Packet 1 ✓
  ├── Packet 2 ✓
  ├── Packet 3 ✗
  ├── Packet 4 ✓
  └── Packet 5 ✗
       ↓
   Receiver
```

Here, packets 3 and 5 were lost.

### Causes

Packet loss can occur because of:

- Network congestion
    
- Faulty cables
    
- Wireless interference
    
- Hardware problems
    
- Buffer overflow
    
- Transmission errors
    

Packet loss can result in:

- Retransmissions
    
- Lower throughput
    
- Poor video/audio quality
    
- Connection problems
    

---

# Important Comparison

|Term|Meaning|Usually Better|
|---|---|---|
|**Bandwidth**|Maximum link capacity|Higher|
|**Throughput**|Actual data transfer rate|Higher|
|**Goodput**|Useful application data rate|Higher|
|**Latency**|Time taken for data to travel|Lower|
|**Delay**|Time spent moving through network|Lower|
|**Jitter**|Variation in packet delay|Lower|
|**Packet Loss**|Percentage/number of lost packets|Lower|

### Easy way to remember

Think about a **water pipe**:

- **Bandwidth** → size of the pipe
    
- **Throughput** → actual amount of water flowing
    
- **Goodput** → useful water reaching the destination
    
- **Latency** → time water takes to reach the destination
    
- **Jitter** → variation in arrival time
    
- **Packet loss** → water that gets lost along the way
    

### Exam Definition

> **Network performance is the measure of how efficiently and effectively a network transfers data, commonly evaluated using bandwidth, throughput, goodput, latency, delay, jitter, and packet loss.**
