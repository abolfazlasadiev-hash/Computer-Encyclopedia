# 8. Reliability

In **computer networks**, **reliability** refers to the ability of a network to **operate correctly and continuously, deliver data successfully, and recover from failures**.

A reliable network should provide communication with **minimum failures and interruptions**.

### Simple Definition

> **Reliability is the ability of a network to provide correct and continuous service despite failures or problems.**

---

## Factors Affecting Network Reliability

### 1. Failure Frequency

A network is more reliable when its components **fail less often**.

Possible failures include:

- Router failure
    
- Switch failure
    
- Cable failure
    
- Server failure
    
- Power failure
    

---

### 2. Fault Tolerance

**Fault tolerance** is the ability of a network to **continue operating even when some components fail**.

For example:

```text
        Router A
        /      \
     Link 1   Link 2
      /          \
   Server A     Server A
```

If one link fails, traffic can use another available path.

This is called **redundancy**.

> **Redundancy → alternative components/paths → higher reliability**

---

### 3. Availability

**Availability** describes how much of the time a network or service is **operational and accessible**.

For example, if a network is available 99.9% of the time, it has very high availability.

A common formula is:

Availability=UptimeUptime+Downtime×100Availability = \frac{Uptime}{Uptime + Downtime} \times 100

Where:

- **Uptime** = time the network works
    
- **Downtime** = time the network is unavailable
    

---

### 4. Recovery

A reliable network should be able to **recover quickly after a failure**.

For example, if a router fails, routing protocols can detect the failure and find another path.

The faster the network recovers, the better its reliability.

---

### 5. Error Control

Networks can experience transmission errors.

Error-control mechanisms help ensure that data arrives correctly.

Examples:

- Error detection
    
- Error correction
    
- Acknowledgements
    
- Retransmission
    

For example, **TCP** can detect missing data and request/recover it through retransmission.

---

## Reliability vs Performance

These two concepts are related but different.

|Reliability|Performance|
|---|---|
|How dependable the network is|How efficiently the network operates|
|Focuses on failures and recovery|Focuses on speed and efficiency|
|Availability is important|Bandwidth and throughput are important|
|Fault tolerance is important|Latency and jitter are important|

### Example

Imagine two networks:

**Network A**

- 1 Gbps
    
- Frequently disconnects
    

**Network B**

- 500 Mbps
    
- Rarely fails and quickly recovers
    

Network A has better **performance**, but Network B may have better **reliability**.

---

## Important Terms

### MTBF — Mean Time Between Failures

The average time a system operates **before a failure occurs**.

Higher MTBF generally means better reliability.

### MTTR — Mean Time To Repair/Recover

The average time required to **repair or recover from a failure**.

Lower MTTR generally means better availability.

---

## Easy Example

Think of a **road network**.

If there is only one road:

```text
A ───────── B
```

If that road is blocked, communication stops.

With multiple roads:

```text
       ┌─────────┐
A ─────┤         ├───── B
       └─────────┘
```

If one road is blocked, another route can be used.

That is **redundancy and fault tolerance**, which improve network reliability.

### Exam Definition

> **Network reliability is the ability of a network to provide continuous and correct communication, minimize failures, tolerate faults, and recover quickly from failures.**
